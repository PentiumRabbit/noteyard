# ADR-001: 排序/筛选在 Go Handler 层处理，不生成动态 SQL

**日期**: 2026-04-30  
**状态**: 已采纳  
**关联需求**: REQ-035

---

## 背景

数据库视图需要支持排序（sort）和筛选（filter）。有两种实现路径：

1. **动态 SQL**：根据查询参数拼接 `ORDER BY` / `WHERE` 子句
2. **Handler 层内存处理**：全量取回行数据后在 Go 里排序/筛选

## 决策

选择方案 2 — Handler 层内存处理（`sort_filter.go`）。

## 理由

| 维度 | 动态 SQL | Handler 内存处理 |
|------|---------|----------------|
| SQL 注入风险 | 需要严格白名单校验列名 | 无风险（列名只用于 map 查找） |
| 实现复杂度 | 高（跨表 JOIN cells，动态参数） | 低（标准 Go slice 操作） |
| 性能 | 好（DB 过滤，减少传输） | 可接受（noteyard 单用户，行数 < 10k） |
| 可维护性 | SQL 拼接难测试 | 纯函数，易单元测试 |
| 多列筛选扩展 | 需要重写 SQL 构建逻辑 | 直接链式调用 `applyFilter` |

SQLite 的 cells 表结构（行列分离）导致动态 SQL 需要复杂的 `EXISTS` 子查询，收益低于风险。

## 后果

- 排序/筛选不持久化，前端 state 维护（刷新后重置）— 符合 REQ-035 设计
- 若未来行数超过 5 万，需重新评估是否迁移到 DB 层处理
- 公式列不可排序/筛选（Handler 层跳过，UI 禁用入口）

## 实现位置

`server/internal/handler/sort_filter.go`
