# ISS-038 — 部分块无法拖动并排（xl-multi-column handleDrop 块识别失败）

| 字段 | 内容 |
|------|------|
| ID | ISS-038 |
| 状态 | 分析中 |
| 优先级 | P1 |
| 发现日期 | 2026-05-05 |
| 发现人 | 用户 |
| 环境 | Tauri 客户端 + 浏览器 |

## 现象

- paragraph / heading / image / callout 等简单块可以拖到另一块边缘触发并排
- database / toggle / columnList 等复杂块拖到边缘时无法触发并排（handleDrop 返回 false）

## 根因分析

`@blocknote/xl-multi-column` 的 `handleDrop` 内部调用链：

```
posAtCoords({ left, top }) → resolvePos → V(state, coords) → Z(bnBlock)
```

1. `posAtCoords` 返回的 pos 是鼠标坐标对应的 ProseMirror 位置，对于 DOM 结构复杂的块（database 内有 table/grid，toggle 内有子编辑器），pos 命中的是内部子节点，而非外层 `blockContainer`
2. `Z(l)` 向上查找最近的 `blockContainer`，但 xl-multi-column 只认识 `bnBlock` group 的节点，database/toggle 等自定义块的 `blockContainer` 包装层在 ProseMirror schema 中 group 是否匹配取决于 BlockNote 的 schema 定义
3. `columnList` 本身 group 是 `childContainer bnBlock blockGroupChild`，不是 `blockGroupChild` 独立的，schema 的 `column` content 规则是 `blockContainer+`，不允许 columnList 嵌套进 column

## 深度根因分析（arch-frontend-ISS038）

### 调用链全貌

```
handleDrop(view, event, slice, moved)
  │
  ├─ posAtCoords({ left: clientX, top: clientY })    → ResolvedPos c
  ├─ V(state, c)                                      → { posBeforeNode, node }  ← 第一个失败点
  ├─ Z(l)  ← getBlockInfo(l)                          → BlockInfo i              ← 第二个失败点
  ├─ view.nodeDOM(l.posBeforeNode).getBoundingClientRect()
  └─ 比较 clientX vs rect.left/right * 0.1 阈值       → s = "left"|"right"|"regular"
       如果 s === "regular"  →  return false  ← 结束，drop 未被处理
```

### 精确根因

#### 根因 1（第 531-534 行）：`V()` 对复杂块的 posBeforeNode 解析路径

`V()` 函数（第 745-752 行）：

```js
function V(o, e) {
  const t = $(o.doc, e.pos);             // $ = getNearestBlockPos
  let n = o.doc.resolve(t.posBeforeNode);
  return n.parent.type.name === "column" && (n = o.doc.resolve(n.before())),
    { posBeforeNode: n.pos, node: n.nodeAfter };
}
```

`getNearestBlockPos`（core 第 6415-6441 行）遍历 `e.pos` 到根节点，找第一个 type 属于 `bnBlock` group 的祖先节点。

关键：`blockContainer` 的 group 是 `"blockGroupChild bnBlock"`（core 第 13677 行），所以对简单块（paragraph/heading），`posAtCoords` 命中的 pos 在 `blockContent` 内，向上能找到 `blockContainer`，返回正确的 `posBeforeNode`。

**对 `database`/`toggle` 等内部 DOM 复杂的块**：
- `database` 渲染了 `<table>`/`<grid>` 等多层 DOM，`content: "none"` 说明其 `blockContent` 节点内容为空（`""` 空字符串）。ProseMirror 对 `content: "none"` 的节点用 `isolating: true` 包裹，`posAtCoords` 落在其 React NodeView 渲染的 DOM 上时，返回的 `pos` 是 **NodeView 外层的 leaf 位置**，并非内部 inline 位置。
- 具体：ProseMirror 的 `posAtCoords` 对于命中 NodeView DOM 的情况，返回 `{ pos: posBeforeNodeView, inside: posBeforeNodeView }`。此时 `pos` 已经指向 `blockContent` 节点本身的起始位置，`getNearestBlockPos` 能正常找到 `blockContainer`，**`V()` 本身不会失败**。

因此根因 1 **不成立**，`V()` 对 `database`/`toggle` 也能正确返回 `blockContainer` 的 `posBeforeNode`。

#### 根因 2（第 534 行）：`nodeDOM(l.posBeforeNode)` 对 blockContainer 返回的 DOM 与坐标不匹配

`blockContainer` 的 renderHTML 返回（core 第 13698-13714 行）：

```js
dom:        <div class="bn-block-outer" data-node-type="blockOuter">
contentDOM: <div class="bn-block"       data-node-type="blockContainer">
```

`view.nodeDOM(posBeforeNode)` 返回的是 **`bn-block-outer`** 元素（ProseMirror nodeDOM 返回该 pos 处节点的 outermost DOM，即 `dom` 属性，不是 `contentDOM`）。

对简单块（paragraph），`bn-block-outer` 的 `getBoundingClientRect()` 覆盖整个行高，宽度等于编辑器宽度，`clientX` 比较容易落在 10% 边缘区域（`k = 0.1`）内，命中 "left"/"right"。

**对 `database`/`toggle` 等高度较大、内容从 `bn-block-outer` 开始占满宽度的块**，`getBoundingClientRect()` 仍然是编辑器宽度，**这一步也不会失败**。

#### 根因 3（真正根因）：`posAtCoords` 对 NodeView 的 `inside` 行为 + `toggle`/`database` 的 React NodeView 拦截 drag 事件

查看 `handleDrop` 第 530-531 行：

```js
handleDrop(t, n, r, u) {
  const c = t.posAtCoords(ye(n));
  if (!c) throw new Error("Could not get event position");
```

`posAtCoords` 对于命中 NodeView 的 DOM 元素，返回 `{ pos, inside }` 其中 `inside >= 0`。**但对于 `database` 这类 `content: "none"` 且 `isolating: true` 的块**，其 React NodeView 渲染的子 DOM（table/grid/iframe 等）**不在 ProseMirror 的 contentDOM 内**，ProseMirror 无法通过 `posAtCoords` 识别这些 DOM 元素，导致 `posAtCoords` 返回 `null`。

**`c` 为 null → 第 532 行 `throw new Error("Could not get event position")`**

这正是用户看到的现象：drop 事件被 handleDrop 处理，但 `posAtCoords` 返回 null，导致抛出异常，ProseMirror 捕获后相当于返回 false，drop 未被处理。

验证依据：
- `database`：`content: "none"`，React NodeView 渲染 `<DatabaseViewErrorBoundary>`，整个内容在 NodeView 的非 contentDOM 区域
- `toggle`：`content: "inline"`，但其 React NodeView 的 `contentRef` 绑定在 `.toggle-summary span` 上，toggle 折叠时 summary 可能高度极小，`posAtCoords` 落在 `.toggle-block` 外层 div 上时同样返回 null
- `callout`：`content: "inline"`，`contentRef` 绑在 `.callout-content div` 上，该 div 与 `.callout-block` 外层之间有 icon 按钮区域，鼠标落在 icon 区域时 `posAtCoords` 返回 null
- 对比 paragraph/heading：内容直接在 contentDOM 内，`posAtCoords` 始终能命中

**补充确认**：`toggle` 和 `database` 不依赖 `posAtCoords` 返回 null，还有第二个失败路径：即使 `c` 非空，`V()` 调用 `getNearestBlockPos` 后 `view.nodeDOM(l.posBeforeNode)` 返回 `bn-block-outer`，`getBoundingClientRect` 仍然正常，因此 **第二失败路径是 `s === "regular"` 判断**：当用户将 database 块拖到另一个 database 块正中间区域时，`clientX` 不在 10% 边缘，`s = "regular"` → `return false`，这是**正常行为**，非 bug。

### 精确代码行定位

| 行号 | 代码 | 失败原因 |
|------|------|---------|
| 531 | `const c = t.posAtCoords(ye(n))` | 鼠标落在 database/callout 的非 contentDOM 区域时返回 null |
| 532-533 | `if (!c) throw new Error(...)` | null 时直接抛出异常而非 return false，导致 drop 未被正确处理 |
| 534 | `const l = V(t.state, c)` | 若 c 非 null 但 pos 在 NodeView 内，V() 仍能正确解析（非失败点） |
| 534 | `Z(l)` = `getBlockInfo(l)` | 若 V() 正确，Z() 也正确（非失败点） |
| 536 | `s === "regular" → return false` | 这是合理的正常路径，非 bug |

**真正根因：第 532-533 行，`posAtCoords` 返回 null 时抛出异常而非安全降级为 `return false`，且对于 `content: "none"` 的自定义 NodeView 块，drag 事件坐标无法被 ProseMirror 正确映射到文档位置。**

## 修复方案

### 方案评估

#### 方案 A：在 Editor.tsx 层完全接管 drop 逻辑（绕过 xl-multi-column handleDrop）

优点：不依赖 xl-multi-column 内部实现，完全可控。
缺点：需要重新实现 handleDrop 的全部逻辑（columnList 操作、列宽归一化、removeBlocks/replaceBlocks），代码量大，与 xl-multi-column 未来版本的 schema 变化可能不兼容。

#### 方案 B：ProseMirror Plugin 前置拦截，修正坐标

优点：不修改 xl-multi-column，在 handleDrop 前先处理。
缺点：两个 Plugin 的 handleDrop 都会被调用，ProseMirror 以第一个返回 true 的为准。需要在 B 中完全复制 xl-multi-column 逻辑，本质上和方案 A 相同。

#### 方案 C：Monkey-patch `V()` 函数（不可行）

`V` 是模块内部闭包函数，未导出，无法 patch。

#### 推荐方案：在 dropOverlayPlugin（已有）的 `handleDrop` 中实现完整逻辑

**在已有的 `dropOverlayPlugin.ts` 里加入 ProseMirror Plugin 的 `handleDrop` 钩子，作为 xl-multi-column handleDrop 的前置代理**，仅处理 `posAtCoords` 返回 null 的情况：通过 `elementFromPoint` + DOM 遍历找到最近的 `bn-block-outer`，再通过 `nodeDOM` 反查 pos，然后将处理委托给重建的 drop 逻辑。

实际上更简洁的方案是：**在 Plugin 的 handleDrop 中，当 `posAtCoords` 返回 null 时，通过 DOM 方法获取真实的 blockContainer pos，然后手动触发与 xl-multi-column 相同的 columnList 创建逻辑**。

### 推荐实现方案（方案 D：扩展 dropOverlayPlugin）

**核心思路**：xl-multi-column 的 handleDrop 在 `posAtCoords` 返回 null 时抛异常。我们在 dropOverlayPlugin 中注册一个优先级更高的 handleDrop，当 xl-multi-column 会失败时接管处理。

**关键 API**：
- `document.elementFromPoint(clientX, clientY)` — 获取鼠标下方真实 DOM 元素
- `el.closest('[data-node-type="blockContainer"]')` — 向上找到 blockContainer DOM
- `view.posAtDOM(containerEl, 0)` — 从 DOM 元素获取 ProseMirror pos
- `getBlockInfo(getNearestBlockPos(doc, pos))` — 获取完整 BlockInfo
- `editor.removeBlocks / editor.replaceBlocks / editor.updateBlock` — 执行 column 操作

**实现步骤**：

```typescript
// dropOverlayPlugin.ts 中新增 handleDrop 钩子

import {
  getNearestBlockPos,
  getBlockInfo,
  nodeToBlock,
  UniqueID,
} from "@blocknote/core";
import type { BlockNoteEditor } from "@blocknote/core";

// 通过 DOM 反查 blockContainer 的 posBeforeNode
function getPosFromDom(view: EditorView, clientX: number, clientY: number): number | null {
  const el = document.elementFromPoint(clientX, clientY);
  if (!el) return null;
  // 向上找 bn-block-outer（blockContainer 的 outermost DOM）
  const outer = (el as HTMLElement).closest('.bn-block-outer') as HTMLElement | null;
  if (!outer) return null;
  // 再找内层 bn-block（ProseMirror 的实际 dom）
  const inner = outer.querySelector('[data-node-type="blockContainer"]') as HTMLElement | null;
  if (!inner) return null;
  try {
    // posAtDOM 返回该 DOM 节点对应的 ProseMirror pos（节点前位置）
    return view.posAtDOM(inner, 0) - 1; // -1 得到 posBeforeNode
  } catch {
    return null;
  }
}

// handleDrop 钩子（注册在 Plugin props 中）
function handleMultiColumnDrop(
  view: EditorView,
  event: DragEvent,
  slice: Slice,
  editor: BlockNoteEditor<any, any, any>
): boolean {
  // 先用标准方式
  let pos = view.posAtCoords({ left: event.clientX, top: event.clientY });

  // 若 posAtCoords 失败，通过 DOM 方式获取
  if (!pos) {
    const rawPos = getPosFromDom(view, event.clientX, event.clientY);
    if (rawPos === null) return false;
    pos = { pos: rawPos, inside: rawPos };
  }

  // 获取 blockContainer 信息（复用 xl-multi-column 的 V() 逻辑）
  let nearestBlock: { posBeforeNode: number; node: any };
  try {
    nearestBlock = getNearestBlockPos(view.state.doc, pos.pos);
    const resolved = view.state.doc.resolve(nearestBlock.posBeforeNode);
    if (resolved.parent.type.name === "column") {
      const colResolved = view.state.doc.resolve(resolved.before());
      nearestBlock = { posBeforeNode: colResolved.pos, node: colResolved.nodeAfter };
    }
  } catch {
    return false;
  }

  const blockInfo = getBlockInfo(nearestBlock);

  // 检查是否在左右 10% 边缘
  const domEl = view.nodeDOM(nearestBlock.posBeforeNode) as HTMLElement | null;
  if (!domEl) return false;
  const rect = domEl.getBoundingClientRect();
  const THRESHOLD = 0.1;
  let side: "left" | "right" | "regular" = "regular";
  if (event.clientX <= rect.left + rect.width * THRESHOLD) side = "left";
  else if (event.clientX >= rect.right - rect.width * THRESHOLD) side = "right";
  if (side === "regular") return false;

  // columnList 块本身不能再被拖成并排
  if (blockInfo.blockNoteType === "columnList") return false;

  // 获取被拖拽块（slice 中第一个 blockContainer）
  if (!slice.content.childCount) return false;
  const draggedNode = slice.content.child(0);
  const schema = editor.schema;
  let draggedBlock: any;
  try {
    draggedBlock = nodeToBlock(
      draggedNode,
      schema.blockSchema,
      schema.inlineContentSchema,
      schema.styleSchema
    );
  } catch {
    return false;
  }

  if (blockInfo.blockNoteType === "column") {
    // 目标块已经在 column 内：向现有 columnList 追加新列
    const columnListNode = view.state.doc.resolve(blockInfo.bnBlock.beforePos).node();
    const columnListBlock = nodeToBlock(
      columnListNode,
      schema.blockSchema,
      schema.inlineContentSchema,
      schema.styleSchema
    );
    // 归一化列宽
    let totalWidth = 0;
    columnListBlock.children.forEach((col: any) => { totalWidth += col.props.width; });
    const avgWidth = totalWidth / columnListBlock.children.length;
    if (avgWidth < 0.99 || avgWidth > 1.01) {
      const factor = 1 / avgWidth;
      columnListBlock.children.forEach((col: any) => { col.props.width *= factor; });
    }
    const targetColIndex = columnListBlock.children.findIndex(
      (col: any) => col.id === blockInfo.bnBlock.node.attrs.id
    );
    const newChildren = columnListBlock.children
      .map((col: any) => ({
        ...col,
        children: col.children.filter((b: any) => b.id !== draggedBlock.id),
      }))
      .filter((col: any) => col.children.length > 0)
      .toSpliced(side === "left" ? targetColIndex : targetColIndex + 1, 0, {
        type: "column",
        children: [draggedBlock],
        props: {},
        content: undefined,
        id: UniqueID.options.generateID(),
      });
    editor.removeBlocks([draggedBlock]);
    editor.updateBlock(columnListBlock, { children: newChildren });
  } else {
    // 目标块不在 column 内：创建新 columnList
    const targetBlock = nodeToBlock(
      blockInfo.bnBlock.node,
      schema.blockSchema,
      schema.inlineContentSchema,
      schema.styleSchema
    );
    if (targetBlock.id === draggedBlock.id) return true; // 拖到自身
    const ordered = side === "left" ? [draggedBlock, targetBlock] : [targetBlock, draggedBlock];
    editor.removeBlocks([draggedBlock]);
    editor.replaceBlocks([targetBlock], [
      {
        type: "columnList",
        children: ordered.map((b: any) => ({ type: "column", children: [b] })),
      },
    ]);
  }

  return true;
}
```

**注册位置**：在 `dropOverlayPlugin()` 返回的 Plugin 的 `props` 中加入：

```typescript
props: {
  handleDrop(view, event, slice, moved) {
    return handleMultiColumnDrop(view, event, slice, editor);
  }
}
```

**Plugin 优先级**：ProseMirror 按 Plugin 数组顺序调用 handleDrop，第一个返回 true 的获胜。需要确保 `dropOverlayPlugin` 在 `multiColumnDropCursor`（xl-multi-column 的 Plugin）**之前**注册。在 Editor.tsx 的 `_tiptapEditor.extensionManager` 或 `useCreateBlockNote` 的 `plugins` 配置中，将 `dropOverlayPlugin` 放在前面。

**Editor.tsx 中注册方式**：

```typescript
const editor = useCreateBlockNote({
  schema,
  // ...
  _tiptapOptions: {
    editorProps: {
      // handleDrop 注册在这里不需要担心优先级，
      // 实际上通过 Plugin 注册优先级更可靠
    }
  }
});

// 在 useMemo 中组装 plugins
const plugins = useMemo(() => [
  dropOverlayPlugin(editor),   // 先注册，优先级高
  // xl-multi-column 的 plugin 由 withMultiColumn 自动添加（后注册）
], [editor]);
```

**注意**：xl-multi-column 的 Plugin 通过 `withMultiColumn(schema)` 注入，其 handleDrop 在遇到 `posAtCoords` 返回 null 时会抛出异常（不是返回 false）。因此即使我们先处理，xl-multi-column 的 Plugin 也可能在我们返回 true 后**不再被调用**（ProseMirror 规范：第一个返回 true 即终止链）。这正是我们想要的。

5. **`getPosFromDom` 辅助函数**：使用 `document.elementFromPoint` + `.closest('.bn-block-outer')` + `view.posAtDOM` 三步获取 pos。注意 `posAtDOM(inner, 0)` 返回的是节点内第一个字符的位置，需要 `-1` 得到 `posBeforeNode`（blockContainer 节点本身的位置）。实际上更准确的方式是遍历 `view.state.doc.descendants` 找到 id 匹配的节点，因为 `posAtDOM` 有时对 NodeView 不准确。推荐做法：从 `outer.dataset.id` 获取 block id，然后用 `getNodeById(id, view.state.doc)` 得到精确 pos。

   ```typescript
   import { getNodeById } from "@blocknote/core";
   
   function getPosFromDom(view: EditorView, clientX: number, clientY: number) {
     const el = document.elementFromPoint(clientX, clientY);
     if (!el) return null;
     const outer = (el as HTMLElement).closest('.bn-block-outer') as HTMLElement | null;
     if (!outer) return null;
     const id = outer.getAttribute('data-id');
     if (!id) return null;
     const result = getNodeById(id, view.state.doc);
     return result ?? null;  // { node, posBeforeNode }
   }
   ```

6. **Editor.tsx 中**：将 `dropOverlayPlugin()` 改为 `dropOverlayPlugin(editor)`，并确认其在 Plugin 数组中位于 xl-multi-column Plugin 之前（通过 `_tiptapOptions.extensions` 或 `useCreateBlockNote` 的 plugin 配置顺序保证）。

7. **columnList 块不能再拖成并排**：在 handleDrop 开头检查 `draggedBlock.type === "columnList"` 时 `return false`，也检查 `targetBlock.type === "columnList"` 时 `return false`（schema 不允许 columnList 嵌套进 column）。

8. **测试用例**：
