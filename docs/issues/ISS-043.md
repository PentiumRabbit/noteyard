## 现象

按钮块配置动作为「打开链接」并填写合法 URL（`https://` 开头）后，点击主按钮无任何响应：不跳转、不弹出警告、无可见副作用。

## 预期行为

1. 按钮块 action = `open_url`、url 为合法 `http/https` 链接时，点击主按钮应在新标签页打开该链接（`window.open(url, "_blank", "noopener,noreferrer")`）。
2. action = `open_url`、url 为空或非 `http/https` 协议时，点击主按钮应弹出提示「URL 不合法：必须以 http:// 或 https:// 开头」，不执行跳转。
3. action = `none` 时，点击主按钮无副作用（现有行为正确）。

## 根因假设

按钮块 `content: "none"` 使 BlockNote/ProseMirror 将其视为 atom 节点（`isAtom = true`，详见 ISS-040）。
ProseMirror 在 `mousedown` 阶段拦截事件并在 `mouseup` 调用 `view.focus()` + `view.dispatch()`，
导致浏览器的 `click` 合成事件被取消或焦点被夺走，React 合成 `onClick` 未能触发。

设置按钮（⚙）已通过将 `mousedown` 处理器改为 `addEventListener("mousedown", handler)` + `e.stopPropagation()` 解决同类问题（ISS-041）；
主按钮的 `handleClick` 仍依赖 React 合成 `onClick`，尚未做等效处理。

## 修复方向

将主按钮（`.button-block-btn`）的点击响应从 React 合成 `onClick` 改为原生 `addEventListener("mousedown", handler)` + `e.preventDefault()` + `e.stopPropagation()`，
在 mousedown 阶段阻断 ProseMirror 的事件拦截，然后在 handler 内执行 `window.open` 或校验逻辑。

具体改动位置：`web/src/components/editor/Editor.tsx`，`ButtonBlock` render 函数，参照 `settingsBtnRef` 的 effect 模式新增 `mainBtnRef` effect。
