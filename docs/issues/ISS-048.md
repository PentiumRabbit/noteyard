## 现象

拖拽排序条目后，条目文本内容前出现多余的 tab 空白字符，导致内容显示错位。

## 复现步骤

1. 在编辑器中创建多个条目
2. 通过拖拽方式对条目进行排序
3. 排序完成后，查看条目文本内容

## 实际结果

条目文本内容前出现多余的 tab 空白字符。

## 预期结果

拖拽排序后条目文本内容保持不变，无多余空白字符。

## 根因

见 `docs/architecture/ISS-048-review.md`。

## 追加记录（2026-05-06）

### 第一次修复验证结果

commit `fb38304`（`dropOverlayPlugin.ts` `side=regular` 改用 BlockNote API）**实测无效**，原因待分析。

### 新增现象（修复尝试过程中引入的回归）

**现象 A**：拖拽后前导空白仍然存在（ISS-048 原始问题未解决）

**现象 B**：拖拽条目后变成并排列（columnList），而非上下排序

**复现步骤（B）**：
1. 创建多个段落条目
2. 拖拽任意条目到另一条目上方或下方
3. 释放后两个条目变成左右并排，而非上下顺序

**预期**：拖拽后条目保持上下排列顺序，位置变更正确。

**当前代码状态**：所有实验性修改已通过 `git stash` 撤销，代码回到 `5ae189a`（第一次修复 commit）。

### 根因确认（2026-05-06 第二次分析）

**现象 A 根因**：`nodeToBlock(slice.content.child(0))` 返回的是含新 ID 的 block 对象（不是文档中的原始 block），`editor.removeBlocks([draggedBlock])` 因 ID 不匹配抛出异常，`event.preventDefault()` 未被调用，浏览器默认 drop 行为触发，插入带空白的内容。
- 修复：从 `dataTransfer.getData("blocknote/html")` 解析出原始 block ID，再从 `editor.document` 中按 ID 查找干净的 block 对象，避免使用 slice 重建的 block。

**现象 B 根因**：`handleMultiColumnDrop` 的 `THRESHOLD=0.1` 与 `DropOverlayView.onDragOver` 的 `SIDE_THRESHOLD=0.15` 不一致，用户看到 regular overlay 但实际落点被判定为 left/right，触发分栏路径。
- 修复：统一两处阈值为同一常量 `SIDE_THRESHOLD`。

**受影响文件**：`web/src/components/editor/dropOverlayPlugin.ts`（唯一需修改文件）

### 修复任务

- T1：`side=regular` 分支改从 `editor.document` 按 ID 查找 draggedBlock，不从 slice 解析
- T2：统一 `THRESHOLD` 和 `SIDE_THRESHOLD` 为同一常量
