## 现象

在数据库表格视图（Table View）中，列头右侧的列宽调整手柄（拖拽分栏功能）无法正常使用，拖拽后列宽不改变。

## 复现路径

1. 打开任意数据库，切换到表格视图
2. 将鼠标移动到列头右侧边缘，预期出现 `col-resize` 光标
3. 按住鼠标左键横向拖动
4. 松手后列宽未发生变化

## 当前实现状态

代码层面实现完整：
- `startResize()` 函数存在，注册 `document` 级 `mousemove` / `mouseup` 事件
- `.col-resize-handle`（6px 宽绝对定位）存在于每个 `<th>` 中
- `<th>` 有 `position: relative`，`colWidths` state 正确绑定到 `style`

## 根因分析

排查后确认根因：`.col-resize-handle`（`position: absolute; right: 0; width: 6px`）被 `.col-header-btn`（`width: calc(100% - 6px); display: flex; height: 100%`）遮挡。

问题在于 `.col-header-btn` 的点击/悬停区域实际覆盖了整个 `<th>` 宽度：
- 在 `display: table-cell` 的 `<th>` 中，`display: flex` 的子元素的 `%` 宽度计算可能在不同浏览器/引擎（尤其 WebKit/Tauri）中不精确，实际渲染宽度超出 `calc(100% - 6px)`
- 即使宽度计算正确，`col-header-btn` 的 `cursor: pointer` 在部分渲染引擎中优先级高于其后 DOM 兄弟元素 `col-resize-handle` 的 `cursor: col-resize`，导致光标不变，用户找不到拖拽区域
- `col-resize-handle` 无任何默认可见样式（无背景色、无边框），用户难以发现 6px 的可交互区域

## 修复方案

1. 给 `.col-resize-handle` 添加 `z-index: 1`，确保其层叠顺序高于 `col-header-btn`
2. 添加常驻视觉指示器：`col-resize-handle` 默认显示一条半透明竖线（右边缘），鼠标悬停时加深，避免用户无法发现交互区域
3. 将 `col-header-btn` 的 `width` 从 `calc(100% - 6px)` 改为 `100%`，并在右侧添加 `padding-right: 6px`，避免依赖 table-cell 的 `%` 计算精度
