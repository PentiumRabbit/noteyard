# ISS-037 — 重启 app 后图片显示 ? 图标（URL 失效）

| 字段 | 内容 |
|------|------|
| ID | ISS-037 |
| 状态 | 已修复 |
| 优先级 | P1 |
| 发现日期 | 2026-05-05 |
| 发现人 | 用户 |
| 环境 | Tauri 客户端 |

## 现象

在编辑器插入图片后，关闭 app 重新打开，图片位置显示 `?` 图标（broken image），图片无法加载。

## 初步分析

图片 URL 在 app 重启后失效。可能原因：
1. 图片存储为临时路径（如 `blob:` URL 或系统 tmp 目录），重启后失效
2. 图片上传后 URL 使用了动态端口（`http://127.0.0.1:<随机端口>/uploads/...`），重启后端口变化导致 URL 失效
3. 图片文件本身未持久化，只存了引用

## 需要排查

1. 检查图片上传后存储的 URL 格式（blob? 绝对路径? 相对路径?）
2. 检查 Go server 上传接口 `/api/uploads`，文件存储位置是否跨重启持久
3. 检查数据库中 image block 存储的 URL 内容
4. 如果 URL 包含动态端口，需改为相对路径（`/uploads/xxx`）或在加载时动态替换端口

## 后端修复方案（arch-backend-ISS037）

### 根因确认

经代码审查确认根因：

- `server/internal/handler/upload_handler.go` L147：`URL: h.baseURL + "/uploads/" + filename`，将 `http://localhost:<port>` 拼入数据库
- `server/cmd/main.go` L109：`handler.NewUploadHandler(uploadDir, fmt.Sprintf("http://localhost:%d", actualPort))`，端口为动态绑定值（port=0 时由 OS 分配），重启后变化

### 改动范围确认

**无邮件通知、外链分享等需要绝对 URL 的功能。** 全局检索结果：
- `server/` 中无 SMTP、webhook、外链分享等使用 baseURL 的代码
- `baseURL` 字段仅被 `upload_handler.go` 的 `Upload()` 方法引用，且只用于构造响应的 `url` 字段

因此将响应改为相对路径是安全的，不影响任何其他功能。

### 具体修改

**文件 1：`server/internal/handler/upload_handler.go`**

- **L55**：`baseURL string` 字段可删除（或保留空置，不影响逻辑）
- **L65–L66**：`NewUploadHandler(uploadDir, baseURL string)` 签名中移除 `baseURL` 参数（或保留但忽略），函数体对应调整
- **L147**：将

  ```go
  URL: h.baseURL + "/uploads/" + filename,
  ```

  改为

  ```go
  URL: "/uploads/" + filename,
  ```

**文件 2：`server/cmd/main.go`**

- **L109**：将

  ```go
  uh := handler.NewUploadHandler(uploadDir, fmt.Sprintf("http://localhost:%d", actualPort))
  ```

  改为

  ```go
  uh := handler.NewUploadHandler(uploadDir)
  ```

  （若选择保留 `baseURL` 参数但传空串，则改为 `handler.NewUploadHandler(uploadDir, "")`）

**文件 3：`server/internal/handler/upload_handler_test.go`**

- `TestUpload_URLFormat`（L112–L130）：断言前缀由 `"http://localhost:8080/uploads/"` 改为 `"/uploads/"`；同时将各测试中 `NewUploadHandler(dir, "http://localhost:8080")` 的第二参数移除或传空串

### 静态文件服务路由

`server/cmd/main.go` L130 的静态文件路由 `/uploads/*` 保持不变，改动不涉及：

```go
r.Handle("/uploads/*", http.StripPrefix("/uploads/", http.FileServer(http.Dir(uploadDir))))
```

### 存量数据迁移

数据库中已有的绝对 URL（如 `http://localhost:8081/uploads/xxx.png`）需要处理。前端兼容方案由 arch-frontend 负责（在渲染时将绝对 URL 中的 host:port 替换为当前 `API_BASE`，或在 DB 中做一次性迁移）。后端无需感知存量数据。

### 改动影响评估

| 检查项 | 结论 |
|--------|------|
| 静态文件服务路由 | 不变，`/uploads/*` 继续正常工作 |
| cleanup_handler.go 中的 `uploadsRefRe` | 匹配 `/uploads/([^"'\s)>]+)`，已兼容相对路径，无需修改 |
| 前端 `uploadFile` 回调（Editor.tsx L537–539） | 使用 `data.url` 作为 src，相对路径需要前端在渲染时补全 host:port（arch-frontend 负责） |
| 邮件/外链分享 | 不存在，无影响 |
| 单元测试 | `TestUpload_URLFormat` 断言需同步更新 |

## 前端修复方案（arch-frontend-ISS037 评审）

### 问题一：新上传 — uploadFile 回调处理相对路径

**位置：** `web/src/components/editor/Editor.tsx`，第 537–540 行

现状代码：

```typescript
uploadFile: async (file: File) => {
  const data = await api.uploads.upload(file);
  return data.url;
},
```

后端改为返回相对路径（`/uploads/<filename>`）后，`data.url` 不再是完整 URL。BlockNote 的 `uploadFile` 回调要求返回浏览器可直接加载的完整 URL。

**改动（第 539 行替换）：**

```typescript
uploadFile: async (file: File) => {
  const data = await api.uploads.upload(file);
  // 后端返回相对路径后需拼接 API_BASE；startsWith("http") 保持过渡期兼容
  const url = data.url.startsWith("http") ? data.url : API_BASE + data.url;
  return url;
},
```

说明：
- `API_BASE` 已在同文件第 31 行从 `../../api/client` 导入，无需新增 import
- `startsWith("http")` 的条件判断使改动在后端切换前后均安全

### 问题二：存量兼容 — 数据库中已有的绝对 URL 规范化

**背景：** 数据库中已存入的 image 块 content 字段格式类似：

```json
[{"type":"image","props":{"url":"http://localhost:54321/uploads/xxx.png"}}]
```

重启后端口变化，这些 URL 直接失效。

**方案：在 `toBlockNote.ts` 的 `buildBlock` 函数中做 URL 规范化**

位置：`web/src/utils/toBlockNote.ts`

**改动一：顶部新增 import（第 4 行之后）**

```typescript
import { API_BASE } from "../api/client";
```

**改动二：在 `buildBlock` 函数之前新增工具函数**

```typescript
const LOCALHOST_UPLOADS_RE = /^http:\/\/localhost:\d+\/uploads\//;

function normalizeUploadUrl(url: string): string {
  if (LOCALHOST_UPLOADS_RE.test(url)) {
    return API_BASE + "/uploads/" + url.split("/uploads/")[1];
  }
  return url;
}
```

**改动三：standard content blocks 分支（第 53–62 行 strikethrough 迁移之後插入）**

在现有 strikethrough→strike 的 `content.map(...)` 结束后、`let props` 之前，追加：

```typescript
// Normalize localhost upload URLs in inline image nodes (ISS-037)
content = content.map((node) => {
  if (node && typeof node === "object") {
    const n = node as Record<string, unknown>;
    if (n.type === "image") {
      const props = n.props as Record<string, unknown> | undefined;
      if (props?.url && typeof props.url === "string") {
        return { ...n, props: { ...props, url: normalizeUploadUrl(props.url) } };
      }
    }
  }
  return node;
});
```

**改动四：props-as-content 分支（第 44–46 行 props 解析后插入）**

`fileAttach` 和 `pdf` 块的 URL 存在 `b.content`（被当作 props 解析），需在该分支也做规范化：

```typescript
// Normalize localhost upload URLs for fileAttach / pdf blocks (ISS-037)
if (
  (b.type === BLOCK_TYPES.FILE_ATTACH || b.type === BLOCK_TYPES.PDF) &&
  typeof props.url === "string"
) {
  props = { ...props, url: normalizeUploadUrl(props.url) };
}
```
