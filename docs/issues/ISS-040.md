## 现象

点击按钮块右侧 ⚙ 打开设置面板后，面板内的输入框无法聚焦/输入，颜色色块无法点击，操作无响应。

## 已尝试

- 移除 `bn-block-content[data-content-type="button"]` 的 `overflow: clip`（943b542）
- 但面板仍不可交互

---

## arch-frontend-ISS040 根因确认（2026-05-05）

### 根因：`content: "none"` → `isAtom = true` → ProseMirror mousedown 拦截 → `view.focus()` 抢焦点

#### 关键代码链路

**1. BlockNote 将 `content: "none"` 映射为空 content 节点（非 atom prop）**

`@blocknote/react/dist/blocknote-react.js` 第 3793 行（`createReactBlockSpec` / `ge` 函数）：
```js
content: e.content === "inline" ? "inline*" : "",   // content:"none" → content:""
selectable: e.isSelectable ?? !0,                    // ButtonBlock 未设置 isSelectable，默认 true
```

ButtonBlock 的 TipTap 节点规格：`content: ""`, `selectable: true`，无 `atom: true`。

**2. ProseMirror 将 `content: ""` 的节点标记为 leaf/atom**

`prosemirror-model/dist/index.js` 第 2125、2130 行：
```js
get isLeaf() { return this.contentMatch == ContentMatch.empty; }  // content:"" → isLeaf=true
get isAtom() { return this.isLeaf || !!this.spec.atom; }           // → isAtom=true
```

ButtonBlock 节点：`isLeaf = true`，`isAtom = true`，`isSelectable = true`（selectable !== false）。

**3. ProseMirror 对 `contentDOM=null` 的 NodeView 自动设置 `contenteditable="false"`**

`prosemirror-view/dist/index.js` 第 1313-1315 行：
```js
if (!contentDOM && !node.isText && dom.nodeName != "BR") {
    if (!dom.hasAttribute("contenteditable"))
        dom.contentEditable = "false";   // ← NodeView 外层 div 被标记为不可编辑
}
```

这对事件拦截并非直接原因，但使 NodeView 整体进入"不可编辑"语义域。

**4. TipTap `stopEvent` 对面板内非交互元素返回 false，允许 ProseMirror 处理**

`@tiptap/core/dist/index.js` 第 5195-5260 行（`NodeView.stopEvent`）：

```js
stopEvent(event) {
    const target = event.target;
    const isInElement = this.dom.contains(target) && !this.contentDOM?.contains(target);
    // contentDOM=null → !undefined → isInElement 等于 this.dom.contains(target)，始终 true

    const isInput = ['INPUT','BUTTON','SELECT','TEXTAREA'].includes(target.tagName)
                    || target.isContentEditable;
    if (isInput && !isDropEvent && !isDragEvent) return true;  // 拦截，PM 不处理

    // ... drag 处理省略 ...

    const isSelectable = NodeSelection.isSelectable(this.node);  // selectable:true → true
    const isClickEvent = event.type === 'mousedown';
    if (isClickEvent && isSelectable) return false;  // ← 不拦截！PM 处理此 mousedown
    return true;
}
```

**结论**：
- 点击 `<input>`、`<button>` → `isInput=true` → `stopEvent=true` → PM 不处理 ✓
- 点击 `<label>` 文本、`<div>`、`<span>` → `isInput=false` + `isClickEvent && isSelectable=true` → `stopEvent=false` → **PM 处理 mousedown**

**5. PM 处理 mousedown 后，mouseup 调用 `updateSelection` → `view.focus()`**

`prosemirror-view/dist/index.js` 第 3302-3321 行：当 `eventBelongsToView` 返回 true（即 `stopEvent` 返回 false）时，PM 的 `handlers.mousedown` 创建 `MouseDown` 对象并注册 `mouseup` 到 `view.root`（= document）。

`prosemirror-view/dist/index.js` 第 3405、3214-3216 行：
```js
// MouseDown.up():
else if (handleSingleClick(this.view, pos.pos, pos.inside, event, this.selectNode)) {
    event.preventDefault();   // ← mouseup 阶段 preventDefault
}

// handleSingleClick → selectClickedLeaf → updateSelection:
function updateSelection(view, selection, origin) {
    if (!view.focused) view.focus();   // ← 焦点还给编辑器
    ...
    view.dispatch(tr);
}
```

`selectClickedLeaf` 第 3228 行：
```js
if (node && node.isAtom && NodeSelection.isSelectable(node)) {
    updateSelection(view, new NodeSelection($pos), "pointer");  // ← isAtom=true 触发
    return true;
}
```

#### 完整触发路径

1. 面板已打开，用户点击面板内的 `<label>` 文字或其他非 INPUT/BUTTON 元素
2. `stopEvent` 对 LABEL 返回 false → `eventBelongsToView` 返回 true → PM `handlers.mousedown` 被调用
3. `MouseDown` 构造，将 `mouseup` 监听器注册到 `document`
4. mouseup 触发 → `handleSingleClick` → `selectClickedLeaf`（因 `isAtom=true`）→ `updateSelection` → **`view.focus()`**
5. `view.focus()` 调用 `.bn-editor.focus()`，将焦点从面板 INPUT 处夺走，或阻止 INPUT 接收焦点

#### 为何 CalloutBlock 不受影响

CalloutBlock 使用 `content: "inline"` → TipTap 节点 `content: "inline*"` → `isLeaf=false` → `isAtom=false`。`selectClickedLeaf` 第 3228 行 `node.isAtom` 为 false，不进入 `updateSelection`，**`view.focus()` 不被调用**。

另外 `content: "inline"` 时 `contentDOM` 非空，ProseMirror 不设置 `contenteditable="false"`。

#### CSS / pointer-events 分析（排除）

- BlockNote CSS (`@blocknote/core/dist/style.css`) 无针对 `content: "none"` 块的 `pointer-events: none` 或 `user-select: none`
- Editor.css 中 `pointer-events: none` 仅出现在 `.bn-drop-overlay`，与按钮块无关
- `z-index: 60` 的面板未被任何 BlockNote UI 覆盖（最高为 1000，在 Mantine 模态组件，与编辑器区域无交叉）

## 修复方案

### 方案 A（推荐）：面板 `onMouseDown` 调用 `stopPropagation`

在 `.button-block-panel` 根 div 上添加 `onMouseDown={e => e.stopPropagation()}`。

`stopPropagation()` 阻止事件冒泡到 `.bn-editor`（ProseMirror 的 `view.dom`），PM 的 `mousedown` handler 永远不会收到来自面板的事件，`MouseDown` 对象不会被创建，`view.focus()` 不会被调用。

**改动位置**：`web/src/components/editor/Editor.tsx` 第 478 行

```diff
- <div className="button-block-panel" ref={panelRef}>
+ <div
+   className="button-block-panel"
+   ref={panelRef}
+   onMouseDown={e => e.stopPropagation()}
+ >
```

**副作用分析**：
- `document` 级别的 mousedown 关闭逻辑：面板内部点击不再冒泡到 document，但 `panelRef.current.contains(target) = true` 本来就不会关闭面板，无功能差异
- 对 React 合成事件无影响（React 19 的事件委托在 React root 处理，stopPropagation 停在 .bn-editor 之前，React root 在 .bn-editor 外层，会继续收到事件）——实际上 React 19 在事件源的最近 React root 处理，stopPropagation 阻止的是 DOM 冒泡，但 React 合成事件通过 nativeEvent 的捕获/冒泡阶段工作，具体参见 React 19 事件机制
- 更安全的写法：改用 `e.nativeEvent.stopImmediatePropagation()` 彻底阻止所有监听器，但 `e.stopPropagation()` 已足够，因为目标是阻止事件到达 `.bn-editor`

### 方案 B：React Portal 将面板挂到 body

使用 `ReactDOM.createPortal(panelJSX, document.body)` 将面板渲染到 body 层级，完全脱离 ProseMirror 的 DOM 树。PM 的 `eventBelongsToView` 检查路径不会经过面板元素，`stopEvent` 不被调用，PM 不处理面板内任何事件。

**改动量**：较大，需要处理面板定位（用 `getBoundingClientRect` 计算 button-block 位置后用 fixed 定位）、close-on-outside-click（现有 document mousedown 逻辑不变，但 `panelRef.current` 需更新为 portal 内的 div ref）。

**不推荐**：改动量比方案 A 大 10 倍，收益相同。

### 方案 C：将 ButtonBlock 的 `content` 改为 `"inline"`

仿照 CalloutBlock 模式，将 ButtonBlock 的 `content` 从 `"none"` 改为 `"inline"`，并提供一个空的 `contentRef` 占位 div。

```tsx
// Editor.tsx
const ButtonBlock = createReactBlockSpec(
  {
    type: "button" as const,
    propSchema: { ... },
    content: "inline",   // ← 改为 inline
  },
  {
    render: ({ block, editor, contentRef }) => {   // ← 新增 contentRef
      ...
      return (
        <div className="button-block">
          <button ...>{label}</button>
          <button ...>⚙</button>
          <div ref={contentRef} style={{ display: "none" }} />  {/* 占位 contentDOM */}
          {panelOpen && <div className="button-block-panel" ref={panelRef}>...</div>}
        </div>
      );
    },
  },
);
```

副作用：`content: "inline"` 会在按钮块内创建一个可编辑的 inline 区域（即使用 `display: none` 隐藏）。按下 Enter/退格在该 inline 区域内可能有意外行为。持久化时 `content` 字段会包含空 inline content。

**不推荐**：副作用不可控，方案 A 更干净。
