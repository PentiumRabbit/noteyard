## 现象

在数据库表格视图（Table View）中，行与行之间无法通过拖拽手柄调整顺序（行排序功能不可用）。

## 与 ISS-025 的关系

ISS-025 是列宽调整手柄失效（代码已实现，功能回归）。  
本 ISS-026 是行拖排序完全缺失（Table View 从未实现此功能），两者根因不同，独立跟踪。

## 根因

Table View 从未实现行级拖拽排序逻辑：`DatabaseView.tsx` 中无任何 `DndContext`/`useSortable` 包裹，且后端缺少对应的 `ReorderRows` 接口（仅 Kanban 视图已实现，Table View 完全空缺）。

## 修复方案

- **后端**（`73b6e67`）：新增 `PATCH /api/databases/:id/rows/reorder` 接口，接收 `row_ids` 数组，批量更新 `order_index`。
- **前端**（`40a91ed`）：在 Table View `<tbody>` 包裹 `DndContext` + `SortableContext`，每行用 `useSortable`，`onDragEnd` 触发 `arrayMove` 更新本地状态并调用后端接口持久化排序。

## 代码现状（修复前）

- `DatabaseView.tsx` Table View 内无任何 `DndContext`、`useSortable` 或行级拖拽逻辑
- `KanbanView.tsx` 已有完整的 `@dnd-kit` 行拖排序（仅 Kanban 视图）
- `ColumnHeader.tsx` 仅在"管理选项"弹窗内有选项行的拖排序
- Table View 行的 `order_index` 字段在 DB schema 层面是否支持持久化排序待确认

## 期望行为

表格视图每行最左侧显示拖拽手柄（`GripVertical` 图标），按住可上下拖动调整行顺序，松手后排序持久化到数据库（更新 `row_order` 或等效字段）。

## 实现要点（供架构师评审）

1. 确认后端 `db_rows` 表是否有 `order_index` 或等效排序字段；若无则需迁移
2. 在 Table View `<tbody>` 包裹 `DndContext` + `SortableContext`，每行用 `useSortable`
3. `onDragEnd` 更新本地 `rows` 顺序（`arrayMove`），同时 PATCH 后端排序
4. 与分组视图（groupByColId）的交互需明确：分组模式下是否禁用行拖排序
