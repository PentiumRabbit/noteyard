## 现象

点击按钮块右侧 ⚙ 打开设置面板后，面板被编辑器容器边缘裁剪，内容显示不全。

### 用户截图补充说明（2026-05-05）

用户提供截图，明确了裁剪的具体范围：

- **可见**：「标签文案」输入框可以完整看到
- **半截**：「颜色」行的色块只露出上半圆，下半被截断
- **完全不可见**：动作类型选择、URL 输入框、确认按钮等后续内容被完全裁掉
- **根因方向**：面板在编辑器可视区域底部被 `overflow` 截断，并非仅位移偏差，而是容器层的 `overflow: hidden/clip` 直接切断了面板内容

---

## 根因分析（arch-frontend，2026-05-05）

### 面板当前定位链

```
.app                           overflow: hidden           (App.css:4)
└── .main                      overflow-y: auto  ← 关键  (App.css:9)
    └── .page-wrap             无 overflow
        └── .editor-wrap       无 overflow
            └── .bn-container  无 overflow（BlockNote）
                └── .bn-editor 无 overflow（BlockNote）
                    └── .bn-block-content[data-content-type="button"]
                        │      无 overflow（已从 overflow:clip 规则中排除，Editor.css:229-236）
                        └── .button-block          position: relative
                            └── .button-block-panel position: absolute; top: calc(100% + 6px)
```

### 根因

`.button-block-panel` 使用 `position: absolute`，其包含块为 `.button-block`（`position: relative`）。

CSS 规范中，`overflow-y: auto`（或 `hidden/scroll`）的元素会成为**滚动容器**，同时作为其后代**绝对定位元素的裁剪边界**。`.main` 设置了 `overflow-y: auto`，当按钮块接近页面可视区域底部时，`position: absolute` 的面板向下扩展超出 `.main` 的可见高度，被 `.main` 的滚动容器裁剪。

**注意**：`overflow: hidden` 的 `.app` 容器层面更高，不是本次的直接裁剪者；`.main` 的 `overflow-y: auto` 才是直接截断面板的根源。

BlockNote 内部（`Block.css`、`editor.css`）没有在 `.bn-block-content` 或 `.bn-editor` 级别设置 `overflow: hidden/clip`，因此 BlockNote 本身不是触发者。

### 为什么前几行可见

面板顶部（标签文案输入框、颜色行上半）在 `.main` 可见视口内，所以部分可见；当面板超出 `.main` 底部边界时才被截断，与截图描述完全吻合。

---

## 修复方案

### 推荐方案：`position: fixed` + JS 坐标计算（改动最小，副作用最低）

**理由**：`position: fixed` 的元素脱离所有滚动容器，直接相对于视口定位，可以完全绕过 `.main` 的裁剪。无需引入 Portal/ReactDOM 依赖，也不需要改变 DOM 结构。

**改动位置**：`web/src/components/editor/Editor.tsx`，`ButtonBlock` 的 render 函数。

**实现要点**：
1. 给 `.button-block` 的外层 `<div>` 添加 `ref`（`wrapRef`），在打开面板时用 `wrapRef.current.getBoundingClientRect()` 获取按钮块的视口坐标。
2. 将坐标通过 state（`panelPos: {top, left}`）传给面板，面板改为 `position: fixed; top: panelPos.top; left: panelPos.left`。
3. 需要处理边界情况：若面板底部超出视口，向上翻转（`top: rect.top - panelHeight`，类似 flip 策略）。
4. CSS 中 `.button-block-panel` 保留所有视觉样式，仅将 `position: absolute` 改为 `position: fixed`，`top/left` 改为通过 inline style 动态注入。

**预期副作用**：
- 页面滚动时面板不随按钮移动（因为 fixed 相对视口，不随滚动容器滚动）。缓解方式：监听 `scroll` 事件关闭面板（panelOpen 设为 false），与点击外部关闭行为一致。
- 面板 z-index 在 fixed 层生效，已有 `z-index: 60` 足够覆盖编辑器工具栏等层级。

**需新增 scroll 监听**（在已有的 `panelOpen` effect 块旁边追加）：
```tsx
React.useEffect(() => {
  if (!panelOpen) return;
  const close = () => setPanelOpen(false);
  window.addEventListener("scroll", close, true); // capture 捕获所有滚动容器
  return () => window.removeEventListener("scroll", close, true);
}, [panelOpen]);
```

### 备选方案：ReactDOM.createPortal 挂 `document.body`

将面板用 `ReactDOM.createPortal(panelJSX, document.body)` 渲染到 body 末尾，同样能逃出所有 overflow 容器。坐标计算逻辑与 fixed 方案相同。

**缺点**：需要在每次 render 里调用 `createPortal`，面板的事件冒泡（`e.stopPropagation()`）不再能阻止 `.main` 的 mousedown 事件，需要检查已有的 native mousedown 拦截逻辑是否仍然有效（ISS-041 修复的 `panelRef` mousedown 阻断在 portal 场景下行为不变，因为直接绑在 panel DOM 上）。整体改动量比 fixed 方案略大。

---

## 结论

**根因**：`.main { overflow-y: auto }` 创建滚动容器，裁剪了其内部 `position: absolute` 的 `.button-block-panel`。

**推荐修复**：改为 `position: fixed` + `getBoundingClientRect()` 动态定位 + scroll 监听关闭面板。

**改动范围**：
- `web/src/components/editor/Editor.tsx`：`ButtonBlock` render 函数，新增 `wrapRef`、`panelPos` state、scroll 监听，面板改为 fixed 定位。
- `web/src/components/editor/Editor.css`：`.button-block-panel` 的 `position`、`top`、`left` 改由 inline style 控制（CSS 中删除或注释这三行）。

**不需要改动**：`.main` 的 overflow 设置、BlockNote 相关 CSS、其他块的定位逻辑。
