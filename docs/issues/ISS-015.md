# ISS-015 — 数据库表格单选/多选字段无法编辑

| 字段 | 内容 |
|------|------|
| ID | ISS-015 |
| 发现时间 | 2026-05-03 |
| 发现来源 | 用户反馈 |
| 状态 | 已修复 |
| 优先级 | P2 |

## 现象

在数据库表格视图中，点击单选（select）或多选（multi-select）类型的单元格，无法进行编辑操作（下拉菜单不弹出或无法交互）。

## 复现步骤

1. 打开任意包含数据库块的页面
2. 确保数据库中存在 select 或 multi-select 类型的列
3. 点击对应类型的单元格
4. 预期下拉选项菜单弹出，实际无响应或无法选择

## 预期结果

点击单选/多选单元格后，弹出选项下拉菜单，可选择或取消选择选项值。

## 实际结果

单元格无法编辑，下拉菜单未弹出或交互失效。

## 根因分析

**分析角色：** arch-frontend-ISS015-116  
**分析时间：** 2026-05-03

### 根因

**核心问题：`openSelectDropdown` / `openMultiSelectDropdown` 在列无预设选项时走 fallback，有选项时正常弹出，但 `status` 类型单元格与 `select` 共用同一 `openSelectDropdown`，行为一致。**

经全量阅读 `DatabaseView.tsx` 和 `CellRenderer.tsx`，定位到以下根因：

#### 1. select / multi-select：options 为空时不弹出下拉菜单（主因）

在 `DatabaseView.tsx` 的 `openSelectDropdown`（第 520–529 行）和 `openMultiSelectDropdown`（第 548–557 行）中，均有如下逻辑：

```
const options = parseOptions(col.options);
if (options.length === 0) {
  startEdit(row.id, col.id, row.cells[col.id] ?? "");
  return;
}
```

当列没有配置任何选项时（`options.length === 0`），函数提前 return，改为调用 `startEdit` 打开一个普通文本输入框——而 `select` / `multi-select` 字段在 `CellRenderer.tsx` 中**不渲染** input（只渲染 `div.cell-select-wrap` + `Chip`），因此 `startEdit` 的输入框由于没有对应 `isEditing` 渲染路径而**无法生效**，最终表现为点击无响应。

**结论：** 当 select/multi-select 列没有提前配置选项时，点击单元格无效。这是 ISS-015 的主要触发路径。

#### 2. status 字段：复用 `openSelectDropdown`，行为与 select 一致

`CellRenderer.tsx` 中，`status` 类型的 `onClick` 也调用 `openSelectDropdown`，而 `status` 列通常在创建时预置了选项（`STATUS_PRESETS`），因此 status 正常情况下不受此 bug 影响。但若 status 列选项被全部删除，同样会触发相同路径。

#### 3. 当 options 非空时，下拉菜单逻辑本身正常

`selectDropdown` 和 `multiSelectDropdown` 状态非空时，在 JSX 中正确渲染了带 `col-menu-overlay`（z-index 99）的遮罩层和 `select-dropdown`（z-index 100）下拉面板，渲染逻辑无误。

#### 4. date / number / text 字段：无类似问题

- `date`、`number`、`text` 均通过 `startEdit` + `isEditing` 路径渲染 input 元素，该路径在 `CellRenderer.tsx` 默认分支中统一处理，逻辑完整。
- 点击后 `editingCell` state 更新，`isEditing` 为 true，input 渲染并聚焦（通过 `useEffect` + `cellInputRef.current?.focus()`）。
- **date / number / text / status（已有选项时）字段无类似问题。**

### 修复方案

**目标**：`select` / `multi-select` 列在没有预设选项时，点击单元格应当弹出一个允许用户输入新选项并保存的交互，而非静默失败。

**方案**：在 `openSelectDropdown` 和 `openMultiSelectDropdown` 中，当 `options.length === 0` 时，**不再 fallback 到 startEdit**（因为 CellRenderer 中 select/multi-select 分支没有 isEditing 渲染），而是仍然弹出下拉面板，面板内显示"暂无选项"提示，并提供"添加选项"快捷入口（触发 `openSelectOptions`，即列头菜单的"管理选项"弹窗）。

**具体改动（限于 `DatabaseView.tsx`）：**

1. `openSelectDropdown`：删除 `options.length === 0` 时提前 return 的 fallback 逻辑；改为始终 `setSelectDropdown`，在 `selectDropdown.options` 为空时，在 JSX 中渲染一条提示信息。
2. `openMultiSelectDropdown`：同上，始终 `setMultiSelectDropdown`，在无选项时渲染提示。
3. `CellRenderer.tsx`：无需改动（click 绑定已正确调用 openSelectDropdown/openMultiSelectDropdown）。
4. JSX 渲染段（select-dropdown 和 multi-select dropdown）：在 `options.length === 0` 时显示 `暂无选项，请先在列头菜单中添加选项` 的提示行。

**同类字段状态结论：**
- `date`：无问题
- `number`：无问题
- `text`：无问题
- `status`：有选项时无问题；选项为空时有相同 fallback 路径（同步修复）

## 排查范围

除单选/多选外，需同步检查以下可编辑字段类型是否存在类似问题：
- 日期（date）字段的日期选择器
- 数字（number）字段的内联编辑
- 文本（text）字段的内联编辑
- 状态（status）字段的下拉交互

关键文件：
- `web/src/components/database/DatabaseView.tsx`（openSelectDropdown、openMultiSelectDropdown、toggleMultiSelectValue）
- `web/src/components/database/CellRenderer.tsx`（单元格点击事件绑定）
