# ISS-017 — Dock 图标尺寸偏大（比 VSCode 大一圈）

## 现象

noteyard 在 macOS Dock 中显示的图标比 VSCode 大一圈，视觉上不协调。

## 环境

- 平台：macOS
- 版本：v0.1.8

## 待分析

根因未明，待总架构师分析。可能原因：
- `icon.icns` 尺寸规格不符合 macOS 标准（macOS Dock 会自动缩放，但 icns 内缺少某些尺寸时会取最大尺寸拉伸）
- `tauri.conf.json` 中图标配置问题

---

## 根因分析（arch#148 · 2026-05-04）

### 结论

**根因：图标设计没有留白边距（padding），内容填满整个 1024×1024 画布，导致在 Dock 中视觉上比其他应用大一圈。**

macOS Dock 所有应用图标占据相同的逻辑点尺寸（由用户 Dock 大小偏好决定），不会因为 icns 内容而自动放大。但视觉上的"大一圈"感完全来自图标设计本身的留白缺失。

### 分析过程

#### 1. 源文件尺寸

| 文件 | 像素尺寸 |
|------|---------|
| `icon.png` | 512×512 |
| `128x128.png` | 128×128 |
| `128x128@2x.png` | 256×256 |
| `64x64.png` | 64×64 |
| `32x32.png` | 32×32 |

**问题**：`icon.png` 只有 512×512，而 `tauri icon` 命令生成 `ic10`（512@2x = 逻辑 512pt，需要 1024px）时只能从 512px 上采样，导致 Retina 屏幕上的 Dock 图标清晰度不足。

#### 2. icon.icns 内部规格

通过解析 icns 二进制结构，确认包含以下 OSType 条目：

| OSType | 逻辑尺寸 | 实际像素 | 字节数 | 备注 |
|--------|---------|---------|--------|------|
| `ic07` | 128×128 @1x | 128×128 | 3,387 | PNG |
| `ic11` | 16×16 @2x | 32×32 | 993 | PNG |
| `ic12` | 32×32 @2x | 64×64 | 1,841 | PNG |
| `ic08` | 256×256 @1x | 256×256 | 6,579 | PNG |
| `ic13` | 128×128 @2x | 256×256 | 6,579 | ic08 的副本 |
| `ic09` | 512×512 @1x | 512×512 | 12,234 | PNG |
| `ic14` | 256×256 @2x | 512×512 | 12,234 | ic09 的副本 |
| `ic10` | 512@2x=1024 | 1024×1024 | 8,325 | **上采样自 512px 源图** |
| `is32` | 16×16 RGB | — | 625 | 旧式 RLE，现代 macOS 不使用 |
| `il32` | 32×32 RGB | — | 1,773 | 旧式 RLE，现代 macOS 不使用 |
| `s8mk` | 16×16 mask | — | 256 | 旧式遮罩，现代 macOS 不使用 |
| `l8mk` | 32×32 mask | — | 1,024 | 旧式遮罩，现代 macOS 不使用 |

**发现的异常**：
- `ic10`（Retina Dock 使用的关键条目）只有 8,325 字节，而 VSCode 同等条目为 197,882 字节（差距 23.8×）——因为 noteyard 的 `ic10` 是从 512px 源图上采样到 1024px，细节仅有 512px 质量
- `ic08 == ic13`（完全相同的字节内容），`ic09 == ic14`（完全相同的字节内容）——@1x 和 @2x 对应条目未使用不同质量来源，而是重复存储同一张图
- 存在 4 个现代 macOS 已弃用的旧式 RLE 条目（`is32/il32/s8mk/l8mk`），占用空间但无实际作用

#### 3. macOS Dock 图标尺寸标准

标准 macOS .icns 应包含以下条目（`tauri icon` 从 1024px 源图生成时产生）：

| OSType | 逻辑尺寸 | 实际像素 |
|--------|---------|---------|
| `ic04` | 16×16 | 16×16 |
| `ic05` | 32×32 | 32×32 |
| `ic07` | 128×128 | 128×128 |
| `ic08` | 256×256 | 256×256 |
| `ic09` | 512×512 | 512×512 |
| `ic10` | 512@2x | **1024×1024**（需真实 1024px 图像） |
| `ic11` | 16@2x | 32×32 |
| `ic12` | 32@2x | 64×64 |
| `ic13` | 128@2x | 256×256 |
| `ic14` | 256@2x | 512×512 |

noteyard 缺少 `ic04`（16×16）和 `ic05`（32×32）条目（VSCode 有），并且 `ic10` 为上采样图，不满足真实高分辨率要求。

#### 4. tauri.conf.json 图标配置

```json
"icon": [
  "icons/32x32.png",
  "icons/128x128.png",
  "icons/128x128@2x.png",
  "icons/icon.icns",
  "icons/icon.ico"
]
```

配置本身格式正确，直接引用了 `icon.icns`。问题不在 tauri 配置，而在 `icon.icns` 的生成来源。

#### 5. 核心根因：图标无留白

对两款应用的 `ic10`（1024×1024）PNG 进行 alpha 通道边界分析：

| 应用 | 内容区域 | 留白 | 内容占比 |
|------|---------|------|---------|
| **noteyard** | 1024×1024 px | **0 px（四边无留白）** | 100% |
| VSCode | 865×845 px | 约 79–100 px 四边 | 约 83% |

**noteyard 的图标内容填满了整个 1024px 画布，没有任何边距。** macOS Dock 会将图标画布等比例展示在固定槽位中，内容满框的图标在视觉上就比有留白的图标"大一圈"。

这是 Dock 图标视觉偏大的直接原因，与 icns 规格或 tauri 配置无关。

### 修复方向

**主要修复（解决视觉偏大）**：

重新生成源图，为图标内容添加约 **10%–12% 的四边留白**：
- 目标画布：**1024×1024 px**（解决上采样问题）
- 内容区域：约 820×820 px（四边各留约 102 px，对应 10% 边距）
- 圆角卡片的实际绘制区域控制在画布 80%–85% 以内，对齐 macOS 系统图标规范

**附带修复（提升 Retina 清晰度）**：

- 将 `icon.png`（tauri 生成源图）升级为 **1024×1024 px**，使 `ic10` 条目包含真实高清内容
- 重新运行 `tauri icon [新icon.png]` 自动生成全部 icns 条目
- 这将同时修复 `ic10` 上采样问题和 `ic04/ic05` 缺失问题

**参考标准**：macOS Human Interface Guidelines 规定 App Icon 在 1024×1024 画布内，内容区域约占 820×820，四边各有约 102 px 安全边距。
