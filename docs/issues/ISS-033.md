# ISS-033 — 浏览器端新建页面显示「编辑器加载失败」

| 字段 | 内容 |
|------|------|
| ID | ISS-033 |
| 状态 | 待修复 |
| 优先级 | P1 |
| 发现日期 | 2026-05-05 |
| 发现人 | 用户 |

## 现象

在**浏览器**（非 Tauri 客户端）打开 noteyard web 页面，点击侧边栏「新建页面」后，编辑器区域显示红色错误框「编辑器加载失败」，无法正常编辑。

- Tauri 客户端打开同一功能正常，无此问题
- 错误由 `ErrorBoundary`（App.tsx line 279/305）捕获，说明 Editor 组件在渲染时抛出异常

## 区别：Tauri vs 浏览器

| 环境 | API base | 表现 |
|------|----------|------|
| Tauri | `localhost:<动态端口>` | 正常 |
| 浏览器 | `localhost:8080`（默认）| 编辑器崩溃 |

- `main.tsx` 在 Tauri 环境通过 `invoke('get_port')` 获取实际端口
- 在浏览器中 `invoke` 不可用，保持默认 `8080`
- 若本地 Go server 跑在 8080，API 正常；但如果 API 请求失败，`toBlockNote` 或 `replaceBlocks` 是否会抛异常导致 ErrorBoundary 触发？

## 需要排查

1. 浏览器打开时 Go server 是否在 8080 运行（排除纯网络失败）
2. 如果 API 成功但 Editor 仍崩溃，检查 ErrorBoundary 捕获的具体错误消息（浏览器 DevTools Console）
3. 检查 REQ-079 期间是否引入了仅在浏览器环境出现的渲染异常（如 Tauri 专属 API 在浏览器调用、`window.__TAURI__` 条件判断缺失等）
4. 检查 `Editor.tsx` 内是否有对 `invoke` 或其他 Tauri API 的直接调用，在浏览器环境会抛出

## 复现步骤

1. 启动 Go server（`make dev` 或 `go run .` 在 noteyard 根目录）
2. 浏览器打开 `http://localhost:5173`（Vite dev server）
3. 侧边栏点击「新建页面」
4. 观察编辑器区域是否显示红色错误框

## 根因分析（arch-frontend，dispatch #173）

**根因**：`web/src/lib/logger.ts` 在 REQ-079 T05 中引入了 **顶层静态 import**：

```ts
import { invoke } from "@tauri-apps/api/core";
```

Vite 在浏览器环境将 `@tauri-apps/api/core` 打包进 bundle。该模块本身不在 import 时抛出，但其 `invoke` 函数在调用时会执行 `window.__TAURI_INTERNALS__.invoke(...)`——在浏览器（非 Tauri WebView）环境下 `window.__TAURI_INTERNALS__` 为 `undefined`，导致 `TypeError: Cannot read properties of undefined (reading 'invoke')`。

虽然 logger.ts 已使用 `if (window.__TAURI__)` 守卫，但**静态 import 本身在浏览器 Vite dev 环境中会触发 `@tauri-apps/api/core` 模块内部的初始化副作用**：模块加载时 `Channel` 类的 `WeakMap` 初始化等调用链在某些 Vite HMR 场景下可能导致模块求值异常，进而导致 `logger` → `api/client` 的模块链初始化失败，`Editor.tsx` 中 `api.blocks.listByPage` 调用时抛出同步异常（若发生在 `useCreateBlockNote` 内部调用链中）。

此外，App.tsx 在切换 Branch2（pageMeta=null）→ Branch1（pageMeta≠null）时会**完全卸载旧 Editor 并挂载新 Editor**（因为两个分支的 JSX 树结构不同，外层包装元素不同），新 Editor 挂载时恰好 `api.blocks.listByPage` 调用失败，ErrorBoundary 捕获到同步渲染错误。

**Tauri 不触发的原因**：Tauri WebView 中 `window.__TAURI_INTERNALS__` 存在且有效，模块初始化正常，invoke 调用成功。

**修复方案**：将 logger.ts 中的静态 import 改为动态 import（在 `__TAURI__` 守卫内部按需引入），彻底消除浏览器环境下的模块副作用。

```ts
// 修复前（静态 import，存在浏览器副作用风险）
import { invoke } from "@tauri-apps/api/core";

// 修复后（动态 import，仅在 Tauri 环境按需加载）
if (typeof window !== "undefined" && (window as any).__TAURI__) {
  import("@tauri-apps/api/core").then(({ invoke }) => {
    invoke("write_frontend_log", { ... }).catch(() => {});
  });
}
```
