## 背景

noteyard 项目经过多个 REQ 迭代（REQ-027 至 REQ-062），前端、后端和 Tauri 集成层已积累大量代码。随着功能增加，可能出现：

- 类型不安全、边界未处理、潜在 panic/crash 等代码质量问题
- 层间职责模糊、模块耦合过紧等架构问题
- 跨组件/跨模块的重复实现，或可抽象复用但未复用的逻辑

本次为专项审查轮次，**只产出审查报告，不进行修复**。修复工作将在后续独立 REQ 中拆解执行。

## 审查维度

### 维度 A — 代码质量

| 子项 | 检查要点 |
|------|----------|
| A1 类型安全 | TypeScript 中 `any` 滥用、类型断言未校验（`as T` 无 guard）；Go 中接口实现不完整、类型转换丢失精度 |
| A2 边界与错误处理 | 数组越界未防御、空指针/nil 解引用未判断；HTTP handler 未覆盖 400/404/500 分支；前端 API 调用缺 catch |
| A3 潜在 Bug | 异步竞态（React state 闭包陷阱、Go goroutine 数据竞争）；事件监听未在卸载时清理（useEffect leak）；SQL 查询缺索引或 N+1 |
| A4 可读性与命名 | 函数/变量命名含糊、魔法数字未常量化、注释与实现不一致 |

### 维度 B — 架构

| 子项 | 检查要点 |
|------|----------|
| B1 层间职责 | handler 是否直接操作 DB（绕过 repository）；前端组件是否直接发 HTTP 请求（绕过 api/client）；业务逻辑是否下沉到 model 层 |
| B2 模块耦合 | 组件间是否存在深层 props drilling；全局状态（settingsStore）是否被不相关模块依赖；Go 包之间是否存在循环依赖风险 |
| B3 Tauri 集成边界 | sidecar 通信协议是否稳定；Rust 层是否承担了本应在 Go 层处理的业务逻辑；Tauri commands 是否过于细碎或重复 |
| B4 数据流一致性 | 前端本地 state 与后端数据的同步策略是否清晰；乐观更新（optimistic update）有无回滚机制 |

### 维度 C — 复用性

| 子项 | 检查要点 |
|------|----------|
| C1 重复组件 | 多个视图（DatabaseView、KanbanView、GalleryView、CalendarView、TimelineView）中是否有相同的 UI 片段可抽取为共享组件 |
| C2 重复工具函数 | 前端各模块中是否存在功能相近的 utils（日期格式化、字符串处理、DOM 操作等） |
| C3 重复后端逻辑 | 多个 handler 中是否存在相似的参数解析、分页、排序逻辑可提取为公共中间件或 helper |
| C4 可抽象 Hook | React 组件中是否有可提取为自定义 hook 的状态逻辑（数据获取、键盘监听、弹窗控制等） |

## 审查报告产出规格

审查完成后，输出一份 `docs/review/CODE-REVIEW-001.md`，结构如下：

1. **执行摘要** — 总体健康评分（1–5）、各维度小结（A/B/C 三维度）
2. **问题清单** — 每个问题包含：
   - 问题 ID（如 `I-001`）
   - 层 / 文件路径 / 行号范围
   - 维度标签（A1–A4 / B1–B4 / C1–C4）
   - 优先级（P0 紧急 / P1 重要 / P2 建议）
   - 问题描述（现象 + 风险）
   - 建议修复方向（不含具体实现，留给后续 REQ）
3. **统计汇总** — 按优先级分组的问题数量、按层分布的问题数量
4. **架构建议** — 不超过 5 条高层架构调整建议
5. **复用机会** — 列出可提取的公共组件/函数/中间件候选清单

## 验收标准

### 可量化指标

- [ ] **问题清单覆盖率**：审查报告中 P0 + P1 问题合计 ≥ 10 条（若实际少于 10 条，需在报告中说明"已全量审查，无更多 P0/P1 问题"）
- [ ] **场景矩阵全覆盖**：场景矩阵 12 个场景均有对应审查结论（即使结论为"未发现问题"也需明确记录）
- [ ] **三层全覆盖**：报告中前端、后端、Tauri 层各至少有 1 个问题条目或明确的"无问题"说明

### 定性标准

- [ ] 每个问题条目包含文件路径和行号范围（泛泛描述不可接受）
- [ ] 建议修复方向不得包含实际代码修改（本轮只审查，不修复）
- [ ] 问题按优先级分类（P0/P1/P2），不得全部标为同一优先级
- [ ] 报告中不包含任何实际代码变更；git diff 为空
