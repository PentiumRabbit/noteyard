## 背景

当前编辑器内通过侧边拖拽手柄（Side Menu drag handle）对块进行拖拽排序时，视觉反馈不足：
- 拖拽过程中，被拖拽的块在原位消失，但用户看不到"块正在跟随鼠标移动"的视觉线索；
- 目标位置的相邻块不会实时"让开"空间，用户无法直观预判释放后的落点位置。

此外，ISS-048（拖拽排序后文本内容前出现多余 tab 空白字符）已在 `dropOverlayPlugin.ts` 中定位根因并完成修复方案设计（详见 `docs/issues/ISS-048.md` 和 `docs/architecture/ISS-048-review.md`），修复代码需纳入本 REQ 统一交付。

本 REQ 聚焦于编辑器内块拖拽的视觉增强，提升拖拽操作的直观性和可预测性。

---

## 目标

1. 拖拽块时，该块以半透明缩略图形式跟随鼠标移动，提供清晰的"正在拖拽"视觉反馈。
2. 拖拽过程中，目标位置的相邻块实时"让开"空间（squeeze/push 动画），直观展示释放后的落点位置。
3. 垂直方向（上下排列的块之间）挤压让位；水平方向保持现有分栏行为（拖到左右边缘自动创建 columnList）。
4. 修复 ISS-048：拖拽排序后文本内容前出现多余 tab 空白字符的 bug。

---

## 功能描述

### FR-1 — 条目跟随（Ghost Element）

**触发条件**：用户在编辑器内通过侧边拖拽手柄（`.bn-side-menu` 内 `[draggable="true"]` 按钮）按下指针开始拖拽。

**操作路径**：
1. 用户在某个块的侧边拖拽手柄上按下鼠标/指针（`pointerdown`）。
2. 系统创建一个该块的 DOM 克隆（ghost element），以 `position: fixed` 定位，`opacity: 0.6` 半透明，`z-index: 100` 置于最上层，`pointer-events: none` 不阻挡鼠标事件。
3. 拖拽过程中（`pointermove`），ghost element 实时跟随鼠标/指针坐标移动。
4. 源块位置覆盖一层半透明遮罩（`rgba(255,255,255,0.55)`），表示该块正在被拖拽。
5. 释放鼠标（`pointerup`）或取消拖拽（`pointercancel`）时，ghost element 和遮罩从 DOM 中移除。

**边界/异常路径**：
- 拖拽过程中 React 重新渲染导致源块 DOM 被替换：通过 `data-id` 属性重新查找源块引用，不中断拖拽。
- 指针移动到编辑器外部：ghost 继续跟随，hit-test 使用编辑器水平中心 + 钳制 Y 坐标确保命中编辑器内块。
- 拖拽到源块自身位置：不显示落点指示线，不触发挤压动画，释放后无操作。

### FR-2 — 挤压效果（Yield/Squeeze Animation）

**触发条件**：拖拽过程中，指针悬停在某个非源块的目标块上方。

**操作路径**：
1. 系统通过 hit-test（编辑器水平中心 + 指针 Y 坐标）确定当前悬停的目标块。
2. 判断拖拽方向（向下拖拽 vs 向上拖拽）和目标块的上下半区（`before` vs `after`）。
3. 计算挤压范围：从源块位置到目标落点位置之间的所有顶层块（非 column 内块）。
4. 对范围内的块应用 `transform: translateY(±sourceHeight)` + `transition: transform 150ms ease`，使其"让开"空间。
5. 范围外的块恢复 `translateY(0)`。
6. 指针移出目标块或移回源块自身时，清除所有挤压变换。

**边界/异常路径**：
- 目标块在 column 内部：挤压动画仅作用于顶层块（`[data-node-type='blockOuter']` 且不在 `[data-node-type='column']` 内），column 内块不参与挤压。
- 拖拽到 columnList 节点上：columnList 整体作为目标，不触发 column 内挤压。
- 快速拖拽（高频 `pointermove`）：DOM 更新通过 `requestAnimationFrame` 节流，避免过度重绘。

### FR-3 — 落点指示线（Drop Line Indicator）

**触发条件**：拖拽过程中，指针悬停在某个非源块的目标块上方。

**操作路径**：
1. 系统在目标块的上边界（`placement === "before"`）或下边界（`placement === "after"`）渲染一条水平指示线。
2. 指示线宽度与目标块 `blockOuter` 宽度对齐，`position: fixed` 定位。
3. 指针移出目标块或移回源块自身时，指示线隐藏。

### FR-4 — 水平分栏（Column Drop）

**行为保持不变**：拖拽到目标块的左边缘 15%（`SIDE_THRESHOLD = 0.15`）或右边缘 15% 时，触发 columnList 创建/追加逻辑。

**与 FR-1/FR-2 的关系**：
- 当前实现（REQ-086）中，水平分栏走 HTML5 原生拖拽路径（`dragover` → `handleMultiColumnDrop`），垂直排序走 pointer events 路径（`pointerdown/move/up`）。
- 本 REQ 不改变分栏逻辑，仅增强垂直拖拽路径的视觉效果。

### FR-5 — ISS-048 修复

**问题**：拖拽排序后，条目文本内容前出现多余的 tab 空白字符。

**根因**：`dropOverlayPlugin.ts` 的 `handleMultiColumnDrop` 对 `side === "regular"` 的普通拖拽原先返回 `false`，交回 ProseMirror 默认处理。ProseMirror 默认 drop 路径使用了 BlockNote `onDragStart` 重建的 `view.dragging.slice`（`openStart=0, openEnd=0`，封闭 Slice），该 Slice 在 `replaceRange` 时因上下文信息不完整，导致 `fillBefore` 在 blockContent 节点前插入了空白文本。

**修复方案**（已在 `dropOverlayPlugin.ts` 中实现）：
1. `side === "regular"` 分支不再返回 `false`，改为使用 BlockNote API（`editor.removeBlocks` + `editor.insertBlocks`）完成块移动，返回 `true`。
2. 统一 `SIDE_THRESHOLD` 常量（dragover 和 handleDrop 共用同一阈值），避免 overlay 显示 regular 但实际落点被判定为 left/right 的不一致。

**受影响文件**：`web/src/components/editor/dropOverlayPlugin.ts`（唯一需修改文件）。

**详细根因分析**：见 `docs/architecture/ISS-048-review.md`。

## 场景矩阵

> 格式见 `docs/engineering/templates/scenario-matrix-template.md`

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 拖拽普通段落块（paragraph）到另一个段落块下方 | ghost 半透明跟随鼠标，目标块下方显示落点指示线，下方块挤压让位，释放后块移动到目标位置，文本内容无多余空白 |
| 输入有效性 | 拖拽块到编辑器外部（浏览器窗口外）释放 | 拖拽取消，ghost 和遮罩清除，块回到原位，无任何 DOM 残留 |
| 输入有效性 | 拖拽块到自身位置释放 | 无落点指示线，无挤压动画，释放后无操作（no-op） |
| 数量/规模边界 | 拖拽单个顶层块（无嵌套子块） | ghost 正常跟随，目标位置相邻块挤压让位，释放后排序正确 |
| 数量/规模边界 | 拖拽带有子块的嵌套块（如折叠列表项） | ghost 包含子块完整克隆，挤压范围覆盖所有受影响的顶层块，释放后父子结构保持完整 |
| 数量/规模边界 | 连续快速拖拽同一个块 3 次 | 每次拖拽 ghost 正确创建和销毁，无 DOM 泄漏，无残留 transform 样式，文本内容始终无多余空白 |
| 前置条件/状态 | 编辑器处于编辑模式，块存在且拖拽手柄可见 | pointerdown 正常触发，ghost 创建成功，拖拽流程完整 |
| 前置条件/状态 | 目标块位于 columnList 内部（分栏布局中） | 挤压动画仅作用于顶层块（column 外），column 内块不受影响；落点指示线正常显示 |
| 前置条件/状态 | 拖拽过程中 React 重新渲染导致源块 DOM 被替换 | 通过 `data-id` 重新查找源块引用，拖拽不中断，ghost 继续跟随 |
| 幂等性/重复调用 | 同一块拖拽到目标位置 A，再拖拽回原位 | 两次拖拽均正确执行，文本内容始终无多余空白，无残留 transform |
| 幂等性/重复调用 | 拖拽到左边缘 15% 区域触发分栏 | 走 HTML5 原生拖拽路径，创建 columnList，ghost 不出现（pointer events 路径不激活），分栏行为与现有逻辑一致 |
| 幂等性/重复调用 | 拖拽到右边缘 15% 区域触发分栏 | 同上，左右分栏行为对称 |

**不适用维度说明**：「来源/优先级」维度不适用，块拖拽是单一用户操作，不涉及多来源输入或优先级覆盖场景。

## 不在范围

- 不涉及侧边栏页面列表拖拽（Sidebar page list drag-and-drop）。
- 不改变现有分栏逻辑（columnList 创建/追加/宽度归一化逻辑保持不变）。
- 不新增块类型或编辑器功能（仅增强现有拖拽的视觉反馈）。
- 不修改 BlockNote 第三方库源码（`node_modules/@blocknote/core/`、`node_modules/prosemirror-view/` 等只读不修改）。
- 不涉及移动端触摸拖拽适配（本 REQ 仅覆盖桌面端 pointer/mouse 事件）。

## 验收标准

- [ ] 拖拽任意块时，半透明 ghost 跟随鼠标/指针移动，释放后 ghost 从 DOM 中正确移除。
- [ ] 拖拽过程中，目标位置的相邻块实时执行 `translateY` 挤压动画（150ms ease），直观展示落点空间。
- [ ] 落点指示线在目标块的上方（`before`）或下方（`after`）正确渲染，宽度与目标块对齐。
- [ ] 拖拽到编辑器外部或按 Escape 取消时，所有视觉元素（ghost、遮罩、挤压变换、指示线）完全清除，块回到原位。
- [ ] ISS-048 修复验证：拖拽排序后，所有块文本内容前无多余 tab 空白字符（覆盖 paragraph、heading、quote、callout 等常见块类型）。
- [ ] 水平分栏行为不受影响：拖拽到左右边缘 15% 区域仍正确触发 columnList 创建/追加。
- [ ] 连续 10 次拖拽操作后，无 DOM 节点泄漏（ghost、overlay、dropLine 均被正确移除），无残留 CSS transform 样式。
- [ ] TypeScript 编译无新增错误或警告。
