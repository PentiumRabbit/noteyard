## 背景

当前 `ColumnsBlock` 使用嵌套 mini-editor（每列一个独立 BlockNote 实例）的方案存在结构性缺陷：
- 列内状态游离于主编辑器文档树之外
- undo/redo 无法感知列内变更
- schema 同步需手动维护，ISS-002/ISS-003 崩溃的根本原因均源于此

## 调研结论（2026-05-01）

**Notion columns 特性**：
- 列数：无明确上限（至少 5 列），当前实现限制 2-4 列
- 列宽：可拖拽调整，按百分比存储，最小宽度有约束
- 列内块类型：几乎无限制，**不支持**嵌套 column_list
- 跨列拖拽：支持
- 数据模型：column_list → column[] → block[]（两层 children 结构）

**BlockNote 0.26 现状**：
- `defaultBlockSpecs` **不包含** columnList/column，无现成实现可直接使用
- 框架对 columnList/column 有内置感知：UniqueID 分配、键盘快捷键（Backspace 合并/拆解）、块移动（flattenColumns）、HTML 导出
- 节点 content 类型已预留：columnList = `"column column+"`，column = `"blockContainer+"`
- 需自行实现 TipTap 节点定义 + React 渲染，注册为 blockSpec

## 目标

重构 columns 块，采用 BlockNote children 结构（columnList → column[] → block[]），消除 mini-editor 方案的结构性缺陷，对齐 Notion 的交互和数据模型。

## 改动范围（初步）

- `web/src/components/editor/Editor.tsx`：删除 ColumnsBlock/ColumnsBlockInner/ColumnCell/columnCellSchema，新增 ColumnListBlock + ColumnBlock
- `web/src/utils/toBlockNote.ts`：适配新 children 数据格式
- `web/src/utils/fromBlockNote.ts`（如有）：同步适配
- 后端 blocks 表/API：支持 children 结构存储
- 存量数据迁移：columnsData JSON prop → children 结构
