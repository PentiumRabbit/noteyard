## 背景

REQ-034 列出附件列 (Files) 为待实现的数据库列类型（P3/中）。附件列允许用户在数据库的每一行中上传或关联多个文件附件，对齐 Notion 的 Files & media 列行为。

现有技术基础：
- 文件上传 API（`POST /api/uploads`，`GET /uploads/{filename}`）来自 REQ-049，当前只允许图片格式（jpg/png/gif/webp），10MB 上限
- 数据库行的单元格值通过 `DBRow.cells: Record<string, string>` 以字符串存储
- `DBColumn.type` 的合法枚举中尚无 `"files"` 类型

---

## 用户故事

作为 noteyard 用户，我希望能在数据库列中为每一行上传和管理多个文件附件，支持图片预览、文件下载、删除，偏好刷新后自动恢复。

## 数据模型

### 列类型

`DBColumn.type` 新增枚举值 `"files"`。

### 单元格值格式

```typescript
interface FileAttachment {
  url: string;   // 服务端存储路径，如 /uploads/xxx.pdf
  name: string;  // 用户可见原始文件名
  size: number;  // 字节数
  mime: string;  // MIME 类型
}
```

单元格值为 `JSON.stringify(FileAttachment[])` 写入 `DBRow.cells[column_id]`。空单元格存 `""` 或 `"[]"`，读取时等价为空数组。

### 上传接口扩展

`POST /api/uploads` 新增支持 MIME 类型：`application/pdf`、`application/msword`、`application/vnd.openxmlformats-officedocument.wordprocessingml.document`、`text/plain`、`text/markdown`、`application/zip`。

响应新增字段：`name`（原始文件名）、`size`（字节数）、`mime`（MIME 类型）。

## 验收标准

- [ ] 「新增列」弹窗中可选「附件」类型，列类型图标为 📎，刷新后持久
- [ ] 上传有效文件后单元格显示文件名 + 类型图标，`cells[column_id]` 为有效 JSON 数组，刷新后仍存在
- [ ] 同一单元格可上传多个文件，逐一删除至 0 后 `cells` 值为 `"[]"` 或 `""`
- [ ] 图片附件悬停显示缩略图 tooltip（≤ 200px），点击新标签页打开
- [ ] 非图片附件点击触发浏览器下载，文件名与上传时一致
- [ ] 上传 > 10MB 文件返回 400，前端提示「文件不超过 10MB」
- [ ] 单元格附件数 ≥ 10 时前端拦截上传，提示「单个单元格最多 10 个附件」
- [ ] 非法 JSON 单元格降级为空，不抛未捕获异常
- [ ] 行详情弹窗与表格视图双向同步，操作后刷新持久
