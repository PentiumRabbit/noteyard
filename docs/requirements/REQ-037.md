# REQ-037: 字体优化

**类型**: UI 优化
**优先级**: P2
**提出日期**: 2026-04-30
**状态**: ✅ 已实现

---

## 用户故事

作为 noteyard 用户，我希望编辑器的字体排版与 Notion 保持一致——中文显示苹方/思源黑体，英文显示系统原生无衬线字体，正文行高宽松，标题字号层级分明——让长时间阅读和编辑更舒适。

---

## 目标字体方案

对齐 Notion 的字体栈设计，具体规格如下：

### 字体栈

| 场景 | 字体栈 |
|------|-------|
| 全局 CSS 变量 | `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif` |
| macOS 中文 | 苹方（PingFang SC）自动命中 |
| Windows 中文 | 微软雅黑（Microsoft YaHei）自动命中 |
| Linux 中文 | 思源黑体（Noto Sans CJK SC）自动命中 |
| macOS 英文 | -apple-system / SF Pro 自动命中 |
| Windows 英文 | Segoe UI 自动命中 |

### 字号与行高规格

| 元素 | 字号 | 行高 | 字重 |
|------|------|------|------|
| 正文（paragraph） | 16px | 1.5 | 400 |
| H1 | 1.875em（30px） | 1.3 | 700 |
| H2 | 1.5em（24px） | 1.3 | 600 |
| H3 | 1.25em（20px） | 1.3 | 600 |
| 代码块（inline/block） | 0.875em（14px） | 1.6 | 400，等宽字体 |
| 数据库单元格 | 14px | 1.4 | 400 |

### 等宽字体栈（代码块）

`"SFMono-Regular", "Menlo", "Monaco", "Consolas", "Liberation Mono", "Courier New", monospace`

## 场景矩阵

| # | 场景 | 验证方式 | 预期效果 |
|---|------|---------|---------|
| 1 | 中文段落 | 在编辑器中输入多行中文正文 | macOS 显示苹方，字号 16px，行高 1.5，阅读舒适无压迫感 |
| 2 | 英文段落 | 输入纯英文段落 | macOS 显示 SF Pro，字号 16px，行高 1.5，与 Notion 英文段落视觉一致 |
| 3 | 三级标题层级 | 依次插入 H1、H2、H3 标题 | H1 30px / H2 24px / H3 20px，字重分别为 700/600/600，层级视觉差异明显 |
| 4 | 无序/有序列表 | 插入多层嵌套列表 | 列表行高与正文一致（1.5），缩进与 Notion 对齐，中英文混排不错位 |
| 5 | 中英混排段落 | 输入包含中英文、数字的混合段落 | 中文苹方与英文 SF Pro 无字形突兀切换，基线对齐 |
| 6 | 数据库表格 | 打开含文本列的数据库视图 | 单元格字号 14px、行高 1.4，表格紧凑但可读 |

## 验收标准

- [ ] 全局字体 CSS 变量已更新为目标字体栈，覆盖编辑器和数据库两个区域
- [ ] macOS 中文正文显示苹方，字号 16px，行高 1.5
- [ ] H1 字号 1.875em（30px）、字重 700；H2 1.5em（24px）、字重 600；H3 1.25em（20px）、字重 600
- [ ] 代码块使用等宽字体栈，字号 0.875em，行高 1.6
- [ ] 数据库单元格字号 14px，行高 1.4
- [ ] Windows 和 Linux 环境下字体回退正常（微软雅黑 / Noto Sans CJK SC）
- [ ] 字体变更不破坏现有行内格式（加粗、斜体、删除线、代码）的视觉效果
- [ ] 与 Notion 截图对比，视觉差异在可接受范围内（无明显偏差）
