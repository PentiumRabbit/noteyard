## 背景

当前设置入口位于侧边栏底部按钮，点击后弹出一个绝对定位浮层（`SettingsPanel.tsx`），锚定在按钮上方。浮层内容包含：字体选择、主题选择、数据目录配置、备份阈值配置、备份状态只读展示。

该交互存在以下问题：

1. **空间局促**：浮层宽度受屏幕边界限制，未来新增更多设置项时扩展性差
2. **交互割裂**：点击浮层外侧即关闭，用户无法同时对照笔记内容调整设置
3. **可发现性差**：浮层没有明确的关闭入口，依赖「点击外部关闭」的隐式交互
4. **与产品定位不符**：Notion 等同类产品均采用设置页整体切换模式，用户预期已被教育

目标：将设置改为独立界面，主内容区整体切换为设置视图，侧边栏保持可见，有明确的返回/关闭入口，所有现有功能全部保留，仅改交互形式。

---

## 功能范围

### F1 — 设置入口（侧边栏）

侧边栏底部「设置」按钮行为由「切换浮层显示/隐藏」改为「切换至设置页面」。

**行为要求：**
- 点击「设置」按钮后，主内容区（`<main class="main">`）切换为设置视图，编辑器区域隐藏
- 侧边栏保持完全可见，页面列表、底部功能按钮均正常可交互
- 侧边栏中「设置」按钮在设置页处于激活态（高亮/选中样式），与页面选中样式保持风格一致
- 进入设置页时，当前正在编辑的页面不丢失（`selectedPageId` 保持，仅视图切换）

---

### F2 — 设置页面布局

设置视图采用「左侧分类导航 + 右侧内容区」双栏布局（类 Notion 设置页风格）。

**布局结构：**

```
┌─────────────────────────────────────────────────────┐
│  侧边栏（保持不变）  │     设置页面（替换主内容区）    │
│                     │  ┌───────────┬──────────────┐ │
│                     │  │ 分类导航  │  设置内容区  │ │
│                     │  │           │              │ │
│                     │  │ 外观      │  （当前分类  │ │
│                     │  │ 数据 & 备份│   的表单）   │ │
│                     │  │           │              │ │
│                     │  └───────────┴──────────────┘ │
└─────────────────────────────────────────────────────┘
```

**分类导航（初始版本）：**

| 分类 key | 显示名 | 包含原有内容 |
|----------|--------|-------------|
| `appearance` | 外观 | 字体选择、主题选择 |
| `data` | 数据 & 备份 | 数据目录、备份阈值、备份数量（只读）、最近备份时间（只读）、保存按钮 |

**行为要求：**
- 默认选中第一个分类（外观）
- 分类切换时，右侧内容区平滑过渡（无需动画，直接切换即可）
- 右侧内容区如有未保存变更，切换分类前不强制提示（字体/主题即时生效；数据&备份保存按钮显式触发）

---

### F3 — 关闭/返回入口

设置页面顶部提供明确的关闭入口。

**行为要求：**
- 设置页右上角提供「× 关闭」或「← 返回」按钮
- 点击后主内容区切换回编辑器视图（恢复 `selectedPageId` 对应的页面，如无则显示空态）
- 支持键盘快捷键 `Esc` 关闭设置页（仅当焦点不在输入框内时响应，避免干扰文本输入）
- 侧边栏「设置」按钮的激活态随之取消

---

### F4 — 现有功能完整保留

从 `SettingsPanel.tsx` 迁移的所有功能，在新设置页中行为不变：

| 功能 | 现有组件位置 | 迁移后位置 |
|------|-------------|-----------|
| 字体选择 | `SettingsPanel` > 字体 section | 设置页 > 外观 > 字体 |
| 主题选择 | `SettingsPanel` > 主题 section | 设置页 > 外观 > 主题 |
| 数据目录输入 | `SettingsPanel` > 数据&备份 section | 设置页 > 数据&备份 > 数据目录 |
| 备份阈值输入 | `SettingsPanel` > 数据&备份 section | 设置页 > 数据&备份 > 备份阈值 |
| 备份数量只读 | `SettingsPanel` > 数据&备份 section | 设置页 > 数据&备份 > 备份信息 |
| 最近备份时间只读 | `SettingsPanel` > 数据&备份 section | 设置页 > 数据&备份 > 备份信息 |
| 保存按钮 + 状态反馈 | `SettingsPanel` > 数据&备份 section | 设置页 > 数据&备份 > 底部操作区 |
| 字体/主题加载状态提示 | `SettingsPanel` > 各 section | 设置页对应分类内 |

`SettingsPanel.tsx` 在本次改造后可删除或保留为 dead code（由实现者决定清理时机）。

## 场景矩阵

| # | 场景 | 前提条件 | 操作 | 预期结果 |
|---|------|----------|------|---------|
| 1 | 正常进入设置页 | 应用已打开，侧边栏可见 | 点击侧边栏底部「设置」按钮 | 主内容区切换为设置页，侧边栏保持不变，「设置」按钮呈激活态 |
| 2 | 设置页内切换分类 | 当前在设置页，选中「外观」 | 点击左侧导航「数据 & 备份」 | 右侧内容区切换为数据&备份表单，外观相关内容隐藏 |
| 3 | 点击关闭按钮返回 | 当前在设置页 | 点击设置页右上角关闭按钮 | 主内容区恢复为进入设置前的编辑器视图，「设置」按钮激活态取消 |
| 4 | Esc 键关闭设置页 | 当前在设置页，焦点不在输入框 | 按 Esc 键 | 与点击关闭按钮行为一致，退出设置页 |
| 5 | 输入框内 Esc 不关闭页面 | 当前在设置页「数据目录」输入框内 | 按 Esc 键 | 不关闭设置页（输入框可自行处理 Esc，如清空输入等），设置页保持打开 |
| 6 | 在设置页操作侧边栏 | 当前在设置页 | 在侧边栏点击一个笔记页面 | 设置页自动关闭，主内容区切换为对应笔记的编辑器视图 |
| 7 | 字体切换即时生效 | 当前在设置页「外观」分类 | 点击一个字体选项 | 字体立即切换，页面字体变化可见，与原浮层行为一致 |
| 8 | 主题切换即时生效 | 当前在设置页「外观」分类 | 点击一个主题选项 | 主题立即切换，全局颜色变化可见，与原浮层行为一致 |
| 9 | 数据&备份保存成功 | 当前在设置页「数据 & 备份」，修改了备份阈值 | 点击「保存」按钮 | 按钮进入 loading 状态，保存成功后显示「已保存」状态反馈，与原浮层行为一致 |
| 10 | 进入设置页不丢失编辑器上下文 | 用户已打开某页面并正在编辑 | 点击「设置」进入设置页，再关闭设置页 | 回到编辑器后，原页面内容完整，编辑器无异常（不触发页面刷新/重新加载） |
| 11 | 侧边栏收起后再进入设置 | 侧边栏处于收起（collapsed）状态 | 展开侧边栏后点击「设置」 | 正常进入设置页，行为与未收起时一致 |

## 验收标准

### 交互验收

- [ ] 点击「设置」按钮后主内容区切换为设置页，侧边栏不消失，场景 1 通过
- [ ] 设置页内分类导航可切换，场景 2 通过
- [ ] 点击关闭按钮和 Esc 键均可退出设置页，场景 3、4 通过
- [ ] 输入框内 Esc 不触发页面关闭，场景 5 通过
- [ ] 在设置页点击侧边栏页面可直接跳转并关闭设置页，场景 6 通过

### 功能验收（可量化）

- [ ] **字体/主题切换响应时间 ≤ 200ms**（从点击到页面字体/主题变化可见），场景 7、8 通过
- [ ] 数据&备份保存流程（loading → 成功/失败提示）与原浮层行为完全一致，场景 9 通过
- [ ] 进出设置页前后，编辑器内容无丢失，`selectedPageId` 不变，场景 10 通过

### 代码质量验收

- [ ] `SettingsPanel.tsx` 中原有浮层逻辑（位置计算 `pos` state、`anchorRef` 参数、点击外部关闭逻辑）在新实现中不再需要，相关代码不应出现在新组件中
- [ ] `Sidebar.tsx` 中 `settingsOpen` state 及触发 `<SettingsPanel>` 渲染的逻辑已迁移或删除
- [ ] 新设置页组件通过 `App.tsx` 的视图层状态控制（如新增 `view: 'editor' | 'settings'` 状态），不由 `Sidebar` 内部控制
