## 背景

按钮块（REQ-054）已支持以下动作类型：`open_url`、`new_subpage`、`edit_page_props`、`none`。

这些动作均为单次、单步操作，无法组合。用户在实际使用中有更复杂的需求，例如：点击一个按钮，同时创建页面、追加内容到当前页面、修改页面属性等多步操作按顺序执行。

REQ-084 在按钮块上新增动作类型 `run_rules`，允许用户配置一个有序的「自动化规则列表」，点击按钮时系统按列表顺序逐条执行每条规则。

---

## 目标

点击配置了 `run_rules` 动作的按钮块后，系统按定义顺序执行用户配置的所有规则，每条规则执行完毕后继续下一条；任意规则失败时中止后续规则并向用户反馈错误，已执行规则的副作用不回滚。

---

## 功能需求

### FR-1 新增 `run_rules` 动作类型

**触发条件**：用户在按钮块设置面板中将「点击动作」选为「运行规则」。

**propSchema 新增字段**：

- `rules`：有序规则列表，JSON 数组，元素类型见 §FR-2。每个按钮块独立持久化自己的规则列表。默认值：`"[]"`（空字符串序列化的 JSON 数组）。

**action 枚举扩展**：`"none" | "open_url" | "new_subpage" | "edit_page_props" | "run_rules"`

**操作步骤（用户侧）**：
1. 打开按钮块设置面板（点击 ⚙ 按钮）。
2. 在「点击动作」下拉中选择「运行规则」。
3. 面板显示规则列表编辑区（详见 §FR-3）。
4. 点击「确认」保存配置；`action` 和 `rules` 字段写入块 props。

**系统响应**：配置保存后，按钮块 UI 无视觉变化（外观同其他动作）；`rules` 字段作为 JSON 字符串持久化到块 props。

**异常/边界路径**：
- `rules` 字段为空数组（`[]`）：点击按钮时直接成功，不执行任何操作，不报错。
- `rules` 字段 JSON 格式非法（由外部直接写入 DB 造成）：点击按钮时忽略解析失败的规则列表，弹出提示「规则配置格式错误，请重新配置」，不执行。
- 切换至其他动作类型再切回 `run_rules`：已保存的规则列表保留不清空；未保存的草稿在切换时重置为上次保存值。

---

### FR-2 规则类型定义

每条规则为一个对象，包含 `type` 字段标识规则类型，以及各类型特有的参数字段。

**规则类型清单**：

| type | 名称 | 参数字段 | 说明 |
|------|------|---------|------|
| `create_page` | 创建页面 | `title`（默认 `"Untitled"`）、`parent: "current" \| "root"` | 在当前页面下或工作区根目录创建子页面 |
| `append_content` | 追加内容 | `text`（文本内容，支持变量占位符，见 §FR-5） | 在当前页面末尾追加一个段落块 |
| `set_page_prop` | 修改页面属性 | `prop: "title" \| "icon" \| "cover"`、`value`（字符串）| 修改当前页面的指定属性 |
| `notify` | 发送通知 | `message`（提示文本，支持变量占位符，见 §FR-5） | 以浮层 toast 形式在页面内展示通知消息 |

**边界规则**：
- 单个按钮块的规则列表上限：**10 条**。超出上限时，设置面板「添加规则」按钮禁用，并显示「最多配置 10 条规则」提示。
- 每条规则类型的参数字段均有默认值，用户可留空使用默认值。

---

### FR-3 规则列表编辑 UI（设置面板扩展）

**触发条件**：设置面板中 `actionDraft === "run_rules"` 时展示规则编辑区。

**UI 布局**（在现有设置面板底部 URL 输入区位置，替换显示）：

```
[规则 1: 创建页面]  [↑] [↓] [删除]
  标题: [Untitled________]
  父级: [当前页面 ▾]
[规则 2: 追加内容]  [↑] [↓] [删除]
  内容: [________________]
[+ 添加规则]
```

**操作步骤（用户配置规则）**：
1. 点击「+ 添加规则」，弹出规则类型选择菜单（4 种类型）。
2. 选择规则类型后，在规则列表末尾新增一条规则行，展开参数输入区。
3. 用户填写参数；输入框 blur 时草稿写入本地状态（不提交 props）。
4. 点击 ↑ / ↓ 调整顺序；点击删除图标移除该规则。
5. 点击设置面板「确认」按钮，将 `action="run_rules"` 和 `rules=[...]` 序列化为 JSON 字符串写入块 props。

**系统响应**：
- 规则顺序调整在本地状态立即生效；未点击「确认」前不持久化。
- 点击「确认」后规则列表刷新；设置面板关闭。
- 重新打开设置面板时，规则列表从已保存的 props 解析并回填。

**异常/边界路径**：
- 规则参数字段为空时允许保存（各字段有默认值）。
- 规则列表为空时允许保存（等价于「点击无效果」）。
- 设置面板因点击外部关闭时，以 `commitPanel` 同步当前草稿到 props（保持现有行为）。

**数量规模边界**：
- 规则列表为空（0 条）：编辑区显示「暂无规则，点击添加」占位文字。
- 规则列表达 10 条：「+ 添加规则」按钮变为禁用状态，tooltip 显示「最多 10 条」。
- 规则列表包含 1 条：「↑」和「↓」均禁用（无法排序）。

---

### FR-4 点击按钮时按顺序执行规则

**触发条件**：用户点击 `action === "run_rules"` 的按钮块主按钮。

**执行流程**：
1. 按钮进入「执行中」状态：禁用点击（防止并发重复触发），按钮文案不变（不展示 loading 文本，通过禁用状态隐式反馈）。
2. 解析 `block.props.rules` JSON；若解析失败则弹出错误提示，退出执行。
3. 规则列表为空时：直接恢复按钮状态，不执行任何操作。
4. 按顺序逐条执行规则（详见各规则类型执行逻辑，§FR-2）。
5. 每条规则执行完毕后，继续下一条，直至全部完成。
6. 全部规则执行成功后：恢复按钮可点击状态；无额外提示（静默成功）。
7. 任意规则执行失败（接口报错、网络错误）：
   - 停止执行后续规则。
   - 弹出错误提示：「规则 {N}（{规则类型名}）执行失败：{错误信息}」。
   - 恢复按钮可点击状态。
   - 已执行规则的副作用（如已创建的页面）**不回滚**。

**各规则类型执行逻辑**：

| type | 执行逻辑 |
|------|---------|
| `create_page` | 调用 `api.pages.create({ parent_id: parentId, title, order_index: 9999 })`；`parent: "current"` 时 `parent_id` 取 `ctxRef.pageId`；`parent: "root"` 时 `parent_id` 取 `null` |
| `append_content` | 调用 `insertOrUpdateBlock(editor, { type: "paragraph", content: resolvedText })`，追加到文档末尾 |
| `set_page_prop` | 调用 `api.pages.update(ctxRef.pageId, { [prop]: resolvedValue })` |
| `notify` | 以系统 toast 展示 `resolvedMessage`；不调用后端接口 |

**异常/边界路径**：
- 按钮正在执行时（处于禁用状态），用户无法再次点击，忽略。
- `ctxRef.pageId` 为空（编辑器未完成加载）：弹出提示「页面未就绪，请稍后重试」，不执行任何规则。
- 某条规则的参数字段经变量替换后为空字符串：仍执行，由各接口/操作的默认行为处理（例如创建页面时 title 为空，则使用 `"Untitled"`）。

---

### FR-5 变量占位符支持（`append_content`、`notify` 规则）

**支持的变量**：

| 占位符 | 替换值 |
|--------|--------|
| `{{page_title}}` | 当前页面标题（从 `ctxRef` 或最近一次 API 响应取） |
| `{{date}}` | 执行时本地日期，格式 `YYYY-MM-DD` |
| `{{time}}` | 执行时本地时间，格式 `HH:mm` |

**替换规则**：
- 执行规则前对 `text` 和 `message` 字段做字符串替换，将已知占位符替换为实际值。
- 未知占位符（不在上表中）保持原样，不报错。
- `{{page_title}}` 无法取到时（ctxRef 未就绪）替换为空字符串。

**不在本期**：更复杂的表达式求值（如数学运算、条件判断）不在此范围。

## 场景矩阵

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | rules 列表包含 2 条规则（create_page + notify），参数均合法 | 顺序执行：页面创建成功，toast 通知弹出 |
| 输入有效性 | rules 列表为空（[]） | 点击按钮后无任何操作，按钮恢复可点击，不报错 |
| 输入有效性 | rules 字段 JSON 非法字符串（外部写入损坏） | 弹出「规则配置格式错误，请重新配置」提示，不执行 |
| 输入有效性 | set_page_prop 规则 value 为空字符串 | 执行 api.pages.update，传入空字符串；接口正常则继续后续规则 |
| 输入有效性 | append_content 规则 text 含 {{date}} 占位符 | 替换为执行时本地日期 YYYY-MM-DD 后追加到页面末尾 |
| 输入有效性 | notify 规则 message 含未知占位符 {{unknown}} | 保持占位符原样不替换，展示含 {{unknown}} 的 toast 文本 |
| 数量/规模边界 | rules 列表恰好 10 条，全部合法 | 全部按顺序执行成功；设置面板「添加规则」按钮禁用 |
| 数量/规模边界 | 已有 10 条规则，尝试在设置面板添加第 11 条 | 「+ 添加规则」按钮保持禁用，tooltip 显示「最多 10 条」，规则数不变 |
| 数量/规模边界 | rules 列表包含 1 条规则 | 顺序按钮（↑↓）均禁用；执行时只运行该条规则 |
| 来源/优先级 | 同一按钮块先保存 rules=[A,B]，后修改为 rules=[B,A] 并再次保存 | 执行时按最新保存的 [B,A] 顺序执行 |
| 来源/优先级 | 设置面板中 action 从 run_rules 切换为 open_url 再切回 run_rules | 已保存的规则列表从 props 回填，未保存草稿丢弃 |
| 前置条件/状态 | ctxRef.pageId 为 null（编辑器未加载完成）时点击按钮 | 弹出「页面未就绪，请稍后重试」，不执行任何规则 |
| 前置条件/状态 | create_page 规则执行时 api.pages.create 网络失败 | 停止后续规则，弹出「规则 N（创建页面）执行失败：{错误信息}」，已执行规则副作用保留 |
| 前置条件/状态 | 规则列表第 2 条失败，第 1 条已成功执行 | 第 1 条副作用不回滚；弹出第 2 条失败提示 |
| 幂等性 | 点击按钮执行规则期间（按钮禁用中）再次点击 | 第二次点击被忽略，不重复执行 |
| 幂等性 | 点击按钮后规则全部执行完成，再次点击 | 规则列表从头重新执行，产生新的副作用（如再次创建页面）；此为预期行为 |

**不适用维度说明**：「来源/优先级—多来源冲突」不适用，规则列表来源单一（设置面板写入 props），无多来源竞争场景；已通过「切换后回填」场景覆盖配置更新优先级。

## 不在本期

- 规则条件判断（if/else 分支，如「若字段值等于 X 则执行」）
- 跨页面操作（如修改其他页面的属性）
- Webhook / 外部 HTTP API 调用规则类型
- 规则执行历史记录与审计日志
- 规则模板（可复用的预设规则列表）
- 撤销（undo）规则已执行的副作用
- 并发执行（当前为顺序串行）
- 变量表达式求值（数学运算、条件表达式）

## 验收标准

- [ ] 按钮块设置面板「点击动作」下拉新增「运行规则」选项；选中后展示规则列表编辑区
- [ ] 规则列表支持添加、删除、排序（↑↓）；支持的规则类型：创建页面、追加内容、修改页面属性、发送通知
- [ ] 规则列表上限 **10 条**：达到上限后「+ 添加规则」按钮禁用，可量化验证（添加第 11 条无效）
- [ ] 点击「确认」后 `action="run_rules"` 和 `rules` 字段持久化，刷新页面后规则配置不丢失
- [ ] 点击按钮时，规则按列表顺序逐条执行；全部成功后按钮恢复可点击状态
- [ ] 任意规则失败时，后续规则停止执行，弹出错误提示说明第几条规则失败及原因
- [ ] 按钮执行期间禁用点击，执行完毕或失败后恢复
- [ ] `append_content` 和 `notify` 规则中 `{{date}}`、`{{time}}`、`{{page_title}}` 占位符正确替换
- [ ] `rules` 字段 JSON 非法时，点击按钮弹出格式错误提示，不执行
- [ ] `tsc --noEmit` 零错误
