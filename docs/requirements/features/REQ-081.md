# REQ-081 文件上传：去格式限制 + 100MB 大小上限

| 字段 | 内容 |
|------|------|
| REQ ID | REQ-081 |
| 版本 | v1.0 |
| 状态 | 待启动 |
| 日期 | 2026-05-05 |
| 类型 | feature |
| 优先级 | P2 |
| 来源 | 用户反馈 |

## 背景

noteyard 目前的文件上传功能对可上传的文件格式有限制，仅允许特定类型的文件。部分用户需要上传格式限制之外的文件（如压缩包、设计稿、二进制文件等），当前限制阻碍了使用。

此外，现有文件大小上限偏低，无法满足较大文件（如高清图片、视频片段、大型文档）的上传需求，用户体验受影响。

本需求旨在解除文件格式限制，并将文件大小上限提升至 100MB，以支持更广泛的使用场景。

---

## 目标

1. 允许用户上传任意格式的文件，不再限定文件类型白名单。
2. 将单次文件上传的大小上限提升至 100MB。

---

## 功能需求

### FR-1 去除文件格式限制

- 文件上传功能不得对文件扩展名或 MIME 类型进行白名单限制。
- 用户可上传任意格式的文件（包括但不限于：文档、图片、音视频、压缩包、二进制文件等）。
- 前端上传入口（文件选择框）不得通过 `accept` 属性限制可选文件类型。
- 后端接口不得因文件类型不在白名单内而拒绝请求。

### FR-2 文件大小上限调整为 100MB

- 单次文件上传允许的最大文件体积为 100MB。
- 超出 100MB 的文件上传请求须被拒绝，并向用户返回明确的错误提示（提示内容应说明文件超出大小限制）。
- 前端在用户选择文件后、发起上传请求前，应对文件大小进行本地校验，超出限制时提前提示用户，不发起无效请求。
- 后端接口同样须执行大小校验，作为最终保障。

---

## 验收标准

| # | 场景 | 预期结果 |
|---|------|---------|
| T1 | 上传一个非常见格式文件（如 `.bin`、`.zip`、`.sketch`） | 上传成功，文件正常保存 |
| T2 | 上传一个大小在 100MB 以内的文件（任意格式） | 上传成功，文件正常保存 |
| T3 | 上传一个大小恰好为 100MB 的文件 | 上传成功，文件正常保存 |
| T4 | 上传一个大小超过 100MB 的文件 | 上传被拒绝，用户收到明确的文件过大提示，不产生残留数据 |
| T5 | 前端文件选择框中可选中任意格式文件（无 `accept` 过滤） | 文件选择器不限制文件类型，用户可选取任意文件 |
| T6 | 后端直接接收超过 100MB 的请求（绕过前端校验） | 后端返回错误响应，拒绝保存 |

---

## 不在范围内

- 文件内容安全扫描（病毒检测、恶意文件识别）。
- 按文件类型分类展示或管理。
- 断点续传或分片上传。
- 存储配额管理（单用户/单空间总存储上限）。
- 对已上传文件的格式或大小的追溯处理。
