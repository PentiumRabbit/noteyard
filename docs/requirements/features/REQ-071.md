## 背景

REQ-063 实现了基础全局搜索（`⌘K` 弹窗、LIKE 子串匹配、标题 + 内容匹配、搜索片段展示）。当前局限：

1. **LIKE 匹配性能差**：页面 / 块数量增多后 `content LIKE '%q%'` 全表扫描明显变慢；且无法利用索引。
2. **跳转不定位**：点击搜索结果仅打开页面，不滚动到匹配的块位置。
3. **无搜索结果分页**：当前硬限 50 条，超过部分丢失。
4. **无搜索历史**：关闭弹窗后搜索词消失，重复搜索需重新输入。

本 REQ 分两个优先级批次交付，不引入外部全文检索引擎（保持单 SQLite 文件的本地优先架构）。

## 范围说明

| 功能 | 本 REQ | 说明 |
|------|--------|------|
| SQLite FTS5 全文索引 | ✅ | 替换 LIKE，性能提升且支持 BM25 排序 |
| 搜索结果跳转并定位到匹配块 | ✅ | 后端返回 `block_id`，前端滚动到对应块 |
| 搜索结果分页（`offset` 参数） | ✅ | 允许加载更多 |
| 搜索历史（最近 10 条搜索词，本地持久化） | ✅ | localStorage，关闭弹窗后保留 |
| 模糊搜索 / 拼音搜索 | ❌ | 不在本期（依赖 ICU 分词，复杂度高） |
| 文件附件内容搜索 | ❌ | 不在本期（需 tika / pdfjs 解析） |

## 技术方案

### T1 — SQLite FTS5 索引

**新增虚拟表**（新建迁移文件）：

```sql
-- 页面标题 FTS
CREATE VIRTUAL TABLE IF NOT EXISTS pages_fts USING fts5(
  title,
  content='pages',
  content_rowid='rowid'
);

-- 块内容 FTS（仅文本块，不索引 props-as-content 类型）
CREATE VIRTUAL TABLE IF NOT EXISTS blocks_fts USING fts5(
  content,
  content='blocks',
  content_rowid='rowid'
);
```

**触发器保持同步**：
```sql
-- pages 触发器
CREATE TRIGGER pages_fts_insert AFTER INSERT ON pages BEGIN
  INSERT INTO pages_fts(rowid, title) VALUES (new.rowid, new.title);
END;
CREATE TRIGGER pages_fts_update AFTER UPDATE ON pages BEGIN
  INSERT INTO pages_fts(pages_fts, rowid, title) VALUES ('delete', old.rowid, old.title);
  INSERT INTO pages_fts(rowid, title) VALUES (new.rowid, new.title);
END;
CREATE TRIGGER pages_fts_delete AFTER DELETE ON pages BEGIN
  INSERT INTO pages_fts(pages_fts, rowid, title) VALUES ('delete', old.rowid, old.title);
END;

-- blocks 触发器（同结构，略）
```

**搜索查询替换**：
```sql
-- 标题匹配（FTS5）
SELECT p.id, p.title, p.icon, p.parent_id
FROM pages_fts
JOIN pages p ON pages_fts.rowid = p.rowid
WHERE pages_fts MATCH ? AND p.deleted_at IS NULL
ORDER BY rank;

-- 内容匹配（FTS5），同时返回匹配的 block_id
SELECT p.id, p.title, p.icon, p.parent_id, b.id AS block_id, snippet(blocks_fts, 0, '<b>', '</b>', '...', 15)
FROM blocks_fts
JOIN blocks b ON blocks_fts.rowid = b.rowid
JOIN pages p ON b.page_id = p.id
WHERE blocks_fts MATCH ? AND p.deleted_at IS NULL
ORDER BY rank
LIMIT ? OFFSET ?;
```

**FTS 初始化**（首次迁移时填充已有数据）：
```sql
INSERT INTO pages_fts(rowid, title) SELECT rowid, title FROM pages;
INSERT INTO blocks_fts(rowid, content) SELECT rowid, content FROM blocks
  WHERE type NOT IN ('database','subpage','fileAttach','bookmark','embed','pdf','button','columnList','column');
```

### T2 — API 变更

`GET /api/search?q=...&limit=20&offset=0`

新增 `offset` 参数；响应中每个内容匹配结果新增 `block_id` 字段：

```typescript
interface SearchResult {
  page_id: string;
  page_title: string;
  page_icon: string | null;
  page_path: string[];
  match_type: "title" | "content";
  snippet: string | null;
  block_id: string | null;  // 新增：内容匹配时的匹配块 ID
}
```

### T3 — 前端：跳转定位

`SearchModal` 点击内容匹配结果时：
1. 调用 `onSelectPage(result.page_id)`
2. 若 `result.block_id` 存在，将其存入 `sessionStorage`（key: `search_target_block`）
3. `Editor` 组件在 `readyRef.current = true` 后检查 `sessionStorage`，若有值则：
   - `editor.getBlock(blockId)` 确认块存在
   - `document.getElementById(blockId)?.scrollIntoView({ behavior: 'smooth', block: 'center' })`
   - 短暂添加 CSS class `.search-highlight`（0.8s 后移除）
   - 清除 `sessionStorage` 中的 key

### T4 — 前端：搜索历史

- 存储：`localStorage` key `noteyard_search_history`，值为 `string[]`（最多 10 条，最新在前）
- 空搜索词时展示历史列表（替换当前"最近访问"区域，两者并存：历史词 + 最近页面）
- 每次执行搜索（非空词，按 Enter 或点击结果）将搜索词 push 到历史
- 历史项旁有 `×` 删除按钮；底部有"清除全部"链接

### T5 — 前端：分页加载更多

- 搜索结果底部：若返回数量 = limit，显示"加载更多"按钮
- 点击后以 `offset += limit` 发起新请求，追加结果到列表
