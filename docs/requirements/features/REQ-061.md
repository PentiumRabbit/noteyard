## 背景

noteyard 当前将数据库文件路径硬编码在 `server/cmd/main.go` 的 `dbFilePath()` 函数中，使用 `os.UserHomeDir()` 拼接固定路径（`~/.local/share/noteyard/noteyard.db`），无法自定义、无自动备份、无版本迁移机制。

随着桌面客户端（REQ-060）落地，用户对数据位置的控制需求、数据安全（备份）需求，以及未来 BlockNote 格式升级的兼容需求，均需在本次需求中系统性解决。

## 功能范围

### F1 — 自定义数据目录

用户可在设置页面修改数据目录。数据目录下同时存放数据库文件（`noteyard.db`）和备份子目录（`backups/`）。

**平台默认数据目录：**

| 平台 | 默认路径 |
|------|---------|
| macOS | `~/Library/Application Support/noteyard/` |
| Windows | `C:\Users\{用户名}\AppData\Roaming\noteyard\` |
| Linux | `~/.local/share/noteyard/` |

**行为要求：**
- 修改目录后，Go server 将数据库文件和 `backups/` 子目录一并迁移到新路径
- 迁移完成前提示用户等待，完成后自动重新打开数据库
- 新目录不存在时自动创建
- 迁移过程中如发生错误，回滚至原目录，并向用户展示错误信息

---

### F2 — 应用内设置页面

在现有「设置」入口实现配置 UI，新增以下字段：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| 数据目录 | 文本输入 + 目录选择器 | 显示当前路径，支持手动输入或通过 Tauri 文件对话框选择 |
| 备份阈值（操作次数） | 数字输入 | 默认 50，范围 1–9999 |

- 保存后配置立即同步写入 `~/.config/noteyard/config.toml`（F3）
- 页面展示当前数据目录下已有备份的数量和最近备份时间（只读展示）

---

### F3 — 配置文件 `~/.config/noteyard/config.toml`

由 Go server 负责读写，与设置页面双向同步。

**文件结构示例：**

```toml
[data]
dir = "/Users/pr/Library/Application Support/noteyard"

[backup]
ops_threshold = 50
```

**行为要求：**
- 应用启动时读取配置文件；文件不存在时写入平台默认值
- 设置页面保存时，Go server 将新值写入配置文件
- 配置文件被外部修改后，下次启动时生效（不需热更新）
- 配置文件读取失败（格式错误等）时，使用默认值并记录日志，不崩溃

---

### F4 — 备份触发逻辑

备份以 .db 文件直接复制实现（F5），触发时机：

1. **按操作次数**：写操作（新建/编辑/删除笔记、页面、数据库记录等）累计达到 `ops_threshold`（可配置，默认 50）次后触发，计数重置为 0
2. **应用退出时**：Tauri 应用收到退出事件时，Go server 触发一次备份（距上次备份操作数 > 0 时才执行）

**行为要求：**
- 操作计数在内存中维护，应用重启后重置为 0
- 备份过程为异步，不阻塞用户操作
- 备份失败时记录日志，不向用户弹出错误（静默降级）

---

### F5 — 备份格式

将 `noteyard.db` 直接复制到数据目录下的 `backups/` 子目录，文件命名规则：

```
noteyard-backup-{YYYY-MM-DD}T{HH-MM-SS}.db
```

示例：`noteyard-backup-2026-05-02T14-30-00.db`

**行为要求：**
- `backups/` 目录不存在时自动创建
- 不限制备份文件数量（本期不做自动清理）
- 备份文件为独立 SQLite 文件，可直接用 SQLite 工具打开

---

### F6 — Schema 迁移

数据库内新增 `schema_migrations` 表，记录已执行的迁移版本。

**表结构：**

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     INTEGER PRIMARY KEY,
    applied_at  TEXT NOT NULL
);
```

**行为要求：**
- 应用启动时，Go server 检查当前最高已迁移版本，依次执行尚未执行的升级脚本
- 每个版本对应一个迁移函数（或 SQL 文件），按版本号顺序执行
- 迁移执行完毕后在 `schema_migrations` 表中写入版本记录
- 迁移失败时终止启动并向用户展示错误，不写入版本记录（保证幂等）
- 初始 schema 视为版本 0，无需记录；第一次结构变更从版本 1 开始

---

### F7 — 内容版本迁移（BlockNote JSON 格式升级）

笔记 `content` 字段新增 `content_version` 整型列（默认值 1），标识该笔记存储的 BlockNote JSON 格式版本。

**表变更：**

```sql
ALTER TABLE notes ADD COLUMN content_version INTEGER NOT NULL DEFAULT 1;
```

（通过 F6 Schema 迁移机制执行，作为迁移版本 N）

**行为要求：**
- 读取笔记时，Go server 根据 `content_version` 决定是否执行格式转换后再返回前端
- 写入笔记时，始终以当前最新 `content_version` 存储，并更新该字段
- 每个版本升级路径对应一个转换函数，按版本链逐步升级（1→2→3…），不跳级
- 当前版本为 1，本期不需要实现实际转换逻辑，只需建立机制框架
- 转换函数注册在代码中（如 `map[int]ContentMigrateFn`），便于后续版本扩展

## 场景矩阵

| # | 模块 | 场景 | 操作 | 预期结果 |
|---|------|------|------|---------|
| 1 | F1 — 数据目录 | 首次启动（macOS） | 安装后第一次打开应用 | 自动创建 `~/Library/Application Support/noteyard/`，`noteyard.db` 和 `backups/` 均初始化在该目录下 |
| 2 | F1 — 数据目录 | 修改数据目录（有效路径） | 在设置页面输入新路径，点击保存 | Go server 将数据库和 backups/ 迁移到新路径，设置页面路径展示更新，操作无感 |
| 3 | F1 — 数据目录 | 修改目录迁移失败 | 新路径无写权限 | 回滚至原目录，设置页面显示错误提示，数据完整 |
| 4 | F2 — 设置页面 | 查看设置 | 打开设置页面 | 显示当前数据目录路径、备份阈值、备份数量、最近备份时间 |
| 5 | F2 — 设置页面 | 修改备份阈值 | 将阈值改为 10，保存 | `config.toml` 中 `backup.ops_threshold` 更新为 10，后续备份触发间隔变为 10 次操作 |
| 6 | F3 — 配置文件 | 配置文件不存在 | 删除 `config.toml`，重启应用 | 自动生成含平台默认值的 `config.toml`，应用正常启动 |
| 7 | F3 — 配置文件 | 配置文件格式错误 | 手动将 `config.toml` 写入非法内容，重启应用 | 使用默认值启动，日志记录解析错误，不崩溃 |
| 8 | F4 — 备份触发（操作次数） | 达到阈值 | 连续执行 50 次写操作（默认阈值） | `backups/` 目录下生成一个新 `.db` 文件，计数重置为 0 |
| 9 | F4 — 备份触发（退出） | 应用退出 | 执行若干写操作后关闭应用窗口 | 应用退出前触发一次备份，`backups/` 中产生新文件 |
| 10 | F4 — 备份触发（退出无操作） | 无写操作后退出 | 打开应用不做任何修改，直接关闭 | 退出时不产生新备份文件 |
| 11 | F5 — 备份格式 | 备份文件命名 | 触发备份后查看 backups/ | 文件名格式为 `noteyard-backup-YYYY-MM-DDTHH-MM-SS.db`，可用 SQLite 工具直接打开 |
| 12 | F6 — Schema 迁移 | 首次启动新版本 | 升级应用后启动 | `schema_migrations` 表中写入新版本记录，数据库结构按脚本更新，日志记录迁移版本 |
| 13 | F6 — Schema 迁移 | 迁移脚本报错 | 迁移脚本含语法错误 | 启动中止，向用户展示迁移失败原因，`schema_migrations` 中不写入新版本，旧数据未损坏 |
| 14 | F6 — Schema 迁移 | 幂等性 | 应用重启（已迁移） | 已执行的迁移版本不重复执行 |
| 15 | F7 — 内容版本 | 读取旧版本笔记 | 数据库中存在 `content_version = 1` 的笔记 | 读取时无转换（版本已是最新），正常返回内容 |
| 16 | F7 — 内容版本 | 写入笔记更新版本字段 | 编辑并保存一条笔记 | 该笔记的 `content_version` 更新为当前最新版本，内容以新格式存储 |
| 17 | F3 + F2 — 双向同步 | 设置保存后验证 | 在设置页面修改阈值，保存后检查 config.toml | `config.toml` 内容与设置页面显示的值完全一致 |
| 18 | F1 — 跨平台默认值 | Windows 首次启动 | 在 Windows 系统首次打开应用 | 数据目录默认为 `C:\Users\{用户名}\AppData\Roaming\noteyard\`，config.toml 写入对应路径 |

## 验收标准

### F1 — 自定义数据目录

- [ ] 各平台首次启动时，数据目录按平台规范默认路径自动创建，场景 1、18 通过
- [ ] 设置页面修改数据目录后，旧目录下 `noteyard.db` 和 `backups/` 完整迁移到新目录，场景 2 通过
- [ ] 迁移失败时数据目录回滚，原数据可正常访问，场景 3 通过

### F2 — 设置页面

- [ ] 设置页面展示：数据目录路径、备份阈值（可编辑）、备份数量、最近备份时间，场景 4 通过
- [ ] 修改备份阈值并保存后，**30 秒内**（或下次操作前）`config.toml` 中对应字段值更新，场景 5 通过（可量化）

### F3 — 配置文件

- [ ] `~/.config/noteyard/config.toml` 在首次启动时自动生成，包含 `[data]` 和 `[backup]` 两个 section，场景 6 通过
- [ ] 配置文件缺失或格式错误时，应用使用默认值正常启动，不崩溃，场景 7 通过

### F4 — 备份触发

- [ ] 写操作累计达到阈值（默认 50 次）后，`backups/` 目录下生成新备份文件，**操作计数归零**，场景 8 通过（可量化：50 次操作触发一次）
- [ ] 应用退出前有写操作时，触发退出备份；无写操作时不生成备份文件，场景 9、10 通过

### F5 — 备份格式

- [ ] 备份文件为 `.db` 扩展名，命名含时间戳，格式为 `noteyard-backup-YYYY-MM-DDTHH-MM-SS.db`，场景 11 通过
- [ ] 备份文件可被 SQLite 客户端（如 DB Browser for SQLite）直接打开且数据完整

### F6 — Schema 迁移

- [ ] 数据库中存在 `schema_migrations` 表，启动日志中记录当前迁移版本号，场景 12 通过
- [ ] 迁移脚本执行失败时应用拒绝启动，`schema_migrations` 表中无新版本记录，场景 13 通过
- [ ] 已迁移版本重启后不重复执行，场景 14 通过

### F7 — 内容版本迁移

- [ ] `notes` 表存在 `content_version` 列，默认值为 1
- [ ] Go server 代码中包含内容迁移函数注册表（`map` 或等价结构），可在不修改读写逻辑主流程的情况下扩展新版本
- [ ] 读取 `content_version = 1` 的笔记时正常返回，不报错，场景 15 通过
- [ ] 保存笔记后 `content_version` 字段为当前最新版本，场景 16 通过
