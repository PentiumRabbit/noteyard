## 背景

用户希望能将笔记内容导出为通用格式，方便迁移、备份内容（区别于 SQLite 文件级备份）或在其他工具中阅读。当前 noteyard 没有内容导出功能。

---

## 范围说明

| 功能 | 本 REQ | 说明 |
|------|--------|------|
| 单页导出为 Markdown | ✅ | 页面标题 + 块内容转 Markdown |
| 单页导出为 JSON | ✅ | 原始 blocks 数组 JSON |
| 全库导出为 Markdown ZIP | ✅ | 所有非删除页面打包为 .zip |
| 全库导出为 JSON ZIP | ✅ | 所有非删除页面打包为 .zip |
| 导出数据库视图（DB Block）| ❌ | 不在本期（结构复杂，另立 REQ） |
| 导出文件附件内容 | ❌ | 不在本期 |

## 场景矩阵

| # | 场景 | 操作 | 预期结果 |
|---|------|------|---------|
| 1 | 单页导出 Markdown | 页面菜单选"导出为 Markdown" | 下载 `<title>.md` 文件，内容包含标题和所有块 |
| 2 | 单页导出 JSON | 页面菜单选"导出为 JSON" | 下载 `<title>.json`，内容为 blocks 数组 JSON |
| 3 | 全库导出 Markdown | 设置页点击"全部导出为 Markdown" | 下载 `noteyard-export-<date>.zip`，每页一个 .md 文件 |
| 4 | 全库导出 JSON | 设置页点击"全部导出为 JSON" | 下载 `noteyard-export-<date>.zip`，每页一个 .json 文件 |
| 5 | 标题特殊字符 | 页面标题含 `/`, `\`, `:` 等 | 文件名中特殊字符替换为 `-`，不报错 |
| 6 | 空页面 | 页面无块 | 导出 Markdown 只有标题行，JSON 为空数组，不报错 |
| 7 | 嵌套块（toggle/callout） | 页面含 toggle 块 | Markdown 中子块缩进展示 |
| 8 | columnList 块 | 页面含并排列 | Markdown 中各列内容顺序输出（不做视觉列布局） |
| 9 | 删除的页面 | 已移入回收站的页面 | 不包含在导出结果中 |
| 10 | 大页面 | 1000+ 块 | 导出正常完成，不超时 |

## 技术方案

### T1 — 后端：单页导出 API

新增两个接口：
- `GET /api/pages/{id}/export?format=markdown` → 返回 `Content-Disposition: attachment; filename="<title>.md"`
- `GET /api/pages/{id}/export?format=json` → 返回 `Content-Disposition: attachment; filename="<title>.json"`

**Markdown 转换规则：**

| 块类型 | Markdown 输出 |
|--------|--------------|
| paragraph | 文本内联内容 |
| heading1/2/3 | `# ` / `## ` / `### ` |
| bulletListItem | `- ` + 内容，子块缩进 2 空格 |
| numberedListItem | `1. ` + 内容 |
| checkListItem | `- [ ] ` / `- [x] ` |
| toggle | `> **内容**`（折叠块，子块缩进） |
| callout | `> 内容` |
| quote | `> 内容` |
| code | ` ```lang\n内容\n``` ` |
| image | `![alt](url)` |
| divider | `---` |
| columnList | 各列内容依次输出，列间空行分隔 |
| column | 直接输出子块 |
| database/subpage/fileAttach/bookmark/embed/pdf/button | `<!-- [block_type] -->` 注释占位 |

**内联内容转换（BlockNote StyledText）：**
- bold → `**text**`
- italic → `*text*`
- strike → `~~text~~`
- code → `` `text` ``
- underline → `<u>text</u>`
- link → `[text](url)`

### T2 — 后端：全库导出 API

新增：
- `GET /api/export?format=markdown` → 返回 ZIP
- `GET /api/export?format=json` → 返回 ZIP

ZIP 内每个文件命名：`<sanitized_title>-<page_id_prefix8>.md/.json`（加 ID 前缀避免同名冲突）。

使用标准库 `archive/zip` 生成，流式写入 response body，`Content-Type: application/zip`。

### T3 — 前端：页面菜单入口

在页面的更多操作菜单（"..."）中新增导出选项：
- "导出为 Markdown"
- "导出为 JSON"

点击后调用 `GET /api/pages/{id}/export?format=...`，触发浏览器下载。

### T4 — 前端：设置页全库导出入口

在设置页"数据与备份"区域新增：
- "全部导出为 Markdown" 按钮
- "全部导出为 JSON" 按钮

点击后调用 `GET /api/export?format=...`，触发浏览器下载。
