## 背景

REQ-086 已实现：ghost 跟随指针 + 蓝色横线指示插入位置。

尚未实现的效果：拖拽过程中，**其他 block 实时向上/向下位移让出空间**，使用户可以直观预判拖拽后的最终排列结果（类 Notion 效果）。

### 技术约束（已验证）

BlockNote 基于 ProseMirror，DOM 由 ProseMirror view 独占管理。在 `requestAnimationFrame` 回调中对 `blockOuter.style.transform` 的修改会被 ProseMirror 在下一次 state flush 时立即 revert，导致视觉上完全没有位移效果。

**因此，直接修改 blockOuter inline style 的方案不可行。**

---

## 目标

拖拽 block 时，源 block 与目标位置之间的其他 block 实时平滑位移（`translateY`），视觉上呈现 Notion 风格的让位效果。

---

## 可行方案

### 方案 A：fixed overlay 模拟（推荐）

**原理**：不修改 ProseMirror 管理的 DOM，而是在 editor 外部创建与每个 block 位置绑定的 `position: fixed` overlay div，通过移动 overlay 模拟 block 位移。

**实现步骤**：
1. `pointerdown` 时：为所有 top-level blockOuter 创建对应的 overlay div（克隆内容，fixed 定位，与 block 完全重叠，pointer-events: none）。同时将原始 blockOuter 设为 `visibility: hidden`（保留空间）。
2. `pointermove` 时：根据拖拽方向，对需要让位的 overlay 应用 `translateY`，其他 overlay 保持原位。
3. `pointerup` 时：销毁所有 overlay，恢复 blockOuter visibility，提交 ProseMirror 事务。

**优点**：完全绕过 ProseMirror DOM 管理限制。
**缺点**：overlay 数量 = block 数量，50+ blocks 时性能需要优化（懒创建/只创建可视区 block）。

### 方案 B：ProseMirror Plugin decoration

**原理**：通过 ProseMirror Decoration API 在 block 节点上添加 CSS class，在 CSS 中用 `transform` + `transition` 实现位移。

**限制**：Decoration 通过 `view.setProps` 触发，本身会导致 DOM 重新 patch，性能和时机不可控，可能与拖拽事件冲突。

---

## 验收标准

- 拖拽 block A 向下经过 block B 时，block B 实时向上位移 `sourceHeight` px（150ms ease 动画）
- 拖拽 block A 向上经过 block B 时，block B 实时向下位移 `sourceHeight` px
- 释放后所有位移清零，ProseMirror 文档结构更新到正确顺序
- 50 个 block 的文档中快速拖拽无卡顿（rAF 节流）
- ISS-048 columnList 分栏路径不受影响
