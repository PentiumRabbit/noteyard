## 背景

noteyard 自 REQ-027 起历经多轮功能迭代，目前已实现：页面树管理、BlockNote 编辑器（含多列/折叠/标注/媒体块）、数据库视图六种（表格/看板/画廊/日历/时间轴/列表）及 14+ 字段类型、全局搜索（REQ-063）、设置页独立界面（REQ-062）、Tauri 桌面客户端（REQ-060）、数据备份与自定义路径（REQ-061）等。

近期完成了 REQ-064/065 全局代码质量修复，Lucide 图标统一（REQ-057/058），以及一批 ISS-001～014 的问题修复。

本文档对当前项目做系统性梳理，识别仍存在的优化方向，为后续排期提供依据。

### P1 — 明显体验缺陷

#### OPT-001 数据库块宽度与视图横向滚动（ISS-006/008）

**问题描述**：看板、日历、时间轴等非表格视图在 BlockNote 编辑器内宽度受限，显示过窄；ISS-006 修复（负 margin 方案）引入了 ISS-008 回归（数据库块超出页面列宽、产生蓝边）。目前 ISS-005/006/007/008 均已有 fix commit，但需验证当前状态是否彻底解决、无回归。

**期望效果**：数据库块与页面正文对齐，非表格视图在块内横向滚动，不超出页面边界，无蓝色聚焦边框。

**来源**：ISS-006、ISS-008

---

#### OPT-002 数据库视图全面对齐 Notion（REQ-059 — 待实现）

**问题描述**：REQ-059 是一个大型待实现 REQ，涉及：
- 表格视图列头编辑弹窗（字段重命名、类型切换）Notion 化
- 筛选/排序/分组面板重构为多条件列表式 UI
- 行详情弹窗顶部添加 BlockNote 内容编辑区
- Select 选项编辑弹窗支持拖拽排序、内联重命名、Notion 风格颜色选择气泡
- 关联选择器支持"新建并关联"
- 新增 phone / people / status 三种字段类型
- 看板/画廊/日历/时间轴样式精细化

**期望效果**：数据库交互体验接近 Notion，高频操作路径顺畅。

**来源**：REQ-059（全量未实现）

#### OPT-003 关联列（REQ-055）与汇总列（REQ-056）缺失

**问题描述**：REQ-055（关联列）和 REQ-056（汇总列）均为"待实现"状态。关联列允许跨数据库行引用，汇总列允许聚合关联行数据，是 Notion 数据库的核心高频功能。没有关联列，用户无法构建跨数据库工作流（如项目表 → 任务表）。

**期望效果**：支持在数据库中添加关联列（选择目标数据库、多选关联行）、汇总列（COUNT/SUM/AVG 等聚合函数）。

**来源**：REQ-055（关联列，待实现）、REQ-056（汇总列，待实现）

**期望效果**：桌面端功能完整可用，REQ 文档状态标记为已实现。

**问题描述**：REQ-063 当前搜索为 LIKE 子串匹配，不支持：

- 搜索结果内跳转到匹配块位置

- 搜索结果分页

这些能力在 REQ-063 中明确标注为"不在范围"，是后续增强点。

**期望效果**：逐步增强搜索能力，提升页面数量多时的查找效率。

**来源**：REQ-063（不在范围条目，后续扩展项）

#### OPT-010 数据导出（Markdown / JSON）

**问题描述**：noteyard 目前没有任何数据导出功能。用户无法将笔记导出为 Markdown 文件或 JSON 备份（区别于 .db 文件备份）。作为本地优先产品，数据可携带性是开源项目的核心价值之一。

**期望效果**：支持单页面导出为 Markdown，支持全量数据导出为 JSON 或 ZIP 包。

**来源**：功能缺口（Notion 核心功能，noteyard 目前完全缺失；REQ-061 明确排除了 JSON/Markdown 导出）

#### OPT-011 Markdown 导入

**问题描述**：与导出对称，noteyard 缺少从外部 Markdown 文件导入内容的能力，用户从其他工具迁移数据成本高。

**期望效果**：支持拖入 Markdown 文件或通过菜单导入，自动转换为 BlockNote 块结构。

**来源**：功能缺口（REQ-061 明确排除了"从外部文件导入"）

---

#### OPT-012 页面封面与图标完善

**问题描述**：当前页面支持封面图和 Emoji 图标，但：
- 随机封面图库（Notion 内置的 Unsplash 渐变/图片库）缺失
- 图标仅支持 Emoji，不支持自定义图片图标
- 页面封面的改/删交互在移动焦点后才出现，可发现性较差

**期望效果**：封面支持从内置图库选择渐变/图片，图标支持上传自定义图片，封面操作按钮常驻可见。

**来源**：功能缺口（Notion 高频 UI 功能对比）

### 技术债

#### TD-001 Columns block 架构迁移（ISS-003 方案C / ISS-002 方案B）

**问题描述**：当前并排（多列）布局的实现方案为"方案A最小修复"——每列是独立的 mini-editor 实例，列数据序列化进 `columnsData` prop，schema/uploadFile 等上下文需手动同步，**undo/redo 无法感知列内变更**。

长期方案是迁移至 BlockNote 原生 `columnList`/`column` ProseMirror 节点（方案C/B），列内容成为文档树一部分，所有能力自动继承（历史、斜杠菜单、工具栏、嵌套块），服务端 children 结构也需适配。

**当前影响**：
- undo/redo 在列内编辑后行为不符合预期
- 列内块类型支持靠手动过滤维护，遗漏新块类型时会崩溃
- 数据序列化路径与其他块不一致，维护成本高

**期望效果**：迁移至 BlockNote 原生 columnList/column 架构，彻底解决 undo/redo 感知、块类型同步、schema 上下文同步等问题。

**来源**：ISS-002（方案B技术债）、ISS-003（方案C，已标注为长期方案）

#### TD-003 服务端孤儿文件（uploads 目录）

**问题描述**：用户上传图片或附件后，如果所在页面或数据库行被删除，`/uploads/` 目录下的文件实体不会被清理（REQ-053 和 REQ-049 均明确排除了孤儿文件清理）。长期使用后磁盘占用难以控制。

**期望效果**：实现定期孤儿文件扫描清理机制（可选：应用启动时、或通过设置页手动触发），删除无引用的上传文件。

**来源**：REQ-053（明确标注为不在范围）

---

#### TD-004 DatabaseView.tsx 体量过大

**问题描述**：`web/src/components/database/DatabaseView.tsx` 已超过 1900 行，承载了数据库视图的全部逻辑。虽然 REQ-059 架构整理阶段提取了 ColorDotPicker、Chip、getPopoverY 等组件，但主文件仍过大，包含列类型、单元格渲染、弹窗、行详情等高度内聚但物理上混合的逻辑。

**期望效果**：将 DatabaseView.tsx 按功能域拆分为子文件（如 `ColumnHeader.tsx`、`RowModal.tsx`、`CellRenderer.tsx` 等），提升可读性和可维护性。

**来源**：REQ-064 全局代码审查结论（文件体量问题）
