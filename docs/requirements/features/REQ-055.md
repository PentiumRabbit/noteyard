## 背景

当前数据库支持的列类型包括 text、number、select 等，均为单数据库内的自包含数据。关联列（Relation）允许一个数据库的每一行引用另一个数据库的一行或多行，实现跨数据库的数据关联，对齐 Notion Relation 列的核心语义。

现有技术基础：
- `DBColumn.type` 通过枚举字符串扩展（已有 12 种类型）
- `DBColumn.options` 字段当前用于 select 选项，以 JSON 字符串存储配置，适合存储关联列的目标数据库 ID
- `database_cells` 单元格值以字符串存储；关联 ID 列表可序列化为 JSON 字符串
- `GET /api/databases/:id` 已返回完整列定义；新增行 ID 查询需要后端增加接口
- `DBColumn` Go 模型已有 `Options` 字段可复用

---

## 用户故事

作为 noteyard 用户，我希望在数据库 A 中添加一个关联列，将 A 的每一行与数据库 B 的一行或多行关联起来，以便在 A 中快速引用 B 中的记录，避免重复输入。

## 数据模型

### 列类型

`DBColumn.type` 新增枚举值 `"relation"`。

### 列配置（options 字段）

```typescript
interface RelationColumnOptions {
  target_database_id: string;   // 关联的目标数据库 ID
  display_column_id?: string;   // 展示目标数据库的哪一列（默认第一列）
}
```

`DBColumn.options` = `JSON.stringify(RelationColumnOptions)`

### 单元格值格式

```typescript
type RelationCellValue = string[];  // 目标数据库的行 ID 数组
```

单元格值为 `JSON.stringify(string[])` 写入 `database_cells.value`。空单元格存 `"[]"` 或 `""`，读取时等价为空数组。

### 新增后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/databases/:id/rows` | 已有；关联选择器复用此接口加载目标行 |
| GET | `/api/databases/:id/rows/:row_id` | 新增；按行 ID 加载单行（用于展示关联标签文案）|

> 关联标签渲染时需根据已选 row ID 查询目标行主列值。为避免 N+1，渲染时批量加载当前视图所有涉及的目标行 ID。

## 验收标准

- [ ] 「新增列」弹窗中可选「关联」类型，并选择目标数据库；列头图标为 🔗，刷新后持久
- [ ] 点击关联列单元格弹出行选择器，展示目标数据库第一列文案，支持多选
- [ ] 单元格展示已选行的标签（主列文案），可逐一删除
- [ ] 操作后 `cells[column_id]` 为合法 JSON 行 ID 数组，刷新后仍存在
- [ ] 目标行被删除后，关联标签显示「已删除」，不崩溃
- [ ] 单元格非法 JSON 降级为空，不抛未捕获异常
- [ ] 行详情弹窗与表格视图双向同步
