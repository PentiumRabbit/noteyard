## 背景

noteyard 的块拖拽排序功能由 `web/src/components/editor/dropOverlayPlugin.ts` 实现，目前基于 HTML5 drag-and-drop API，拖拽时仅在目标块上叠加一个蓝色半透明填充框（`bn-drop-overlay`）。

用户反馈此体验不直观：
- 无法明确看出块将被插入到目标块的**上方还是下方**；
- 被拖拽的块在拖拽过程中没有半透明 ghost 跟随效果，视觉上缺乏「正在移动」的感知；
- 其他块不会实时让位，无法预判最终排列结果；
- 整体体验与 Notion 等同类产品存在明显差距。

经技术评估，HTML5 drag-and-drop API 对 ghost 样式、其他块实时位移均有根本性限制，无法通过增量修补达到目标体验。

**REQ-086 v2.0 决策：完全放弃 HTML5 drag-and-drop，改用 pointer events 手动实现拖拽系统**，使 block 可以实时移动、其他 block 实时让位，达到与 Notion 一致的拖拽体验。

---

## 目标

拖拽块时，实现与 Notion 一致的交互体验：
1. 被拖拽块以半透明 ghost 形式实时跟随指针移动；
2. 其他块在拖拽过程中**实时让位**（真实 DOM 位移），用户可即时预判最终排列结果；
3. 目标插入位置以蓝色横线明确指示（上方或下方）；
4. 释放后块落入正确位置，动画平滑，无闪烁。

---

## 核心技术决策

**放弃 HTML5 drag-and-drop，改用 pointer events 手动实现拖拽系统。**

原因：
- HTML5 drag API 的 ghost 图像由浏览器完全控制，无法实现半透明实时跟随；
- HTML5 drag API 期间无法操作其他块的 DOM 位置（浏览器限制），无法实现实时让位；
- pointer events（`pointerdown` / `pointermove` / `pointerup`）对 DOM 操作无任何限制，可完全自主控制拖拽视觉。

实现模式（类 Notion）：
- `pointerdown` 在拖拽手柄上触发，记录起始位置；
- `pointermove` 期间：ghost 元素（绝对定位，跟随指针）实时更新坐标；同时计算命中的目标块，将其他块通过 `transform: translateY` 实时让位；
- `pointerup` 触发：提交 ProseMirror 事务完成块位置变更，清理所有临时 DOM 与 transform。

## 功能需求

### FR-1 pointer events 拖拽引擎（核心）

**触发条件**：用户在拖拽手柄上按下（`pointerdown`）。

**操作步骤**：
1. `pointerdown` 触发，系统记录拖拽起始块（`sourceBlock`）和指针初始坐标。
2. 系统调用 `element.setPointerCapture(pointerId)`，确保后续 `pointermove` / `pointerup` 事件不会因指针移出元素而中断。
3. 原块设置为半透明占位（`opacity: 0.3`），表示「正在被移动」。
4. 系统创建 ghost 元素：克隆原块 DOM，`position: fixed`，`pointer-events: none`，`opacity: 0.6`，初始坐标与原块对齐。
5. `pointermove` 持续触发，ghost 元素实时跟随指针坐标更新位置。
6. `pointerup` 触发，ghost 元素销毁，原块恢复正常透明度，提交最终排序结果。

**系统响应**：
- 整个拖拽过程中页面不触发文字选中（`user-select: none` 在拖拽开始时设置，结束后恢复）。
- `pointercancel` 事件（如系统手势打断）：执行与 `pointerup` 相同的清理逻辑，不留残留状态。

**异常/边界路径**：
- `pointerdown` 时找不到目标块 DOM：不进入拖拽状态，不报错。
- `setPointerCapture` 失败（非标准环境）：降级为不捕获，`pointermove` 仍可工作但可能在边缘丢失事件；不崩溃。
- 拖拽过程中编辑器卸载：`destroy()` 执行清理（移除 ghost、恢复 transform、恢复 opacity），不产生内存泄漏。

---

### FR-2 其他块实时让位（核心）

**触发条件**：`pointermove` 期间，指针进入新的目标块区域。

**操作步骤**：
1. 系统根据指针 Y 坐标，计算当前命中的目标块（`targetBlock`）及插入位置（上方/下方）。
2. 系统对文档中所有块计算需要位移的方向：
   - 位于 `sourceBlock` 与插入点之间的块：向反方向位移（让出空间）；
   - 其余块：`transform: translateY(0)`（无位移）。
3. 位移量 = `sourceBlock` 的高度，方向由拖拽方向（向上/向下）决定。
4. 所有 transform 变更通过 CSS transition（`transition: transform 150ms ease`）平滑过渡。
5. 指针继续移动时，让位计算实时重新执行，块位移实时更新。

**系统响应**：
- 所有让位均为视觉位移（`transform`），不修改 ProseMirror 文档结构；文档结构变更仅在 `pointerup` 时通过事务提交。
- 插入位置以蓝色横线（2px，`rgba(59, 130, 246, 0.9)`）叠加显示，与让位效果同步更新。

**异常/边界路径**：
- 目标块与源块相同：不触发让位，不显示指示线。
- 文档只有 1 个块：不触发让位逻辑，ghost 正常跟随，`pointerup` 后位置不变。
- 快速移动导致 `pointermove` 频率过高：通过 `requestAnimationFrame` 节流，每帧最多计算一次让位，不卡顿。

---

### FR-3 拖拽提交与清理（核心）

**触发条件**：`pointerup` 或 `pointercancel` 事件触发。

**操作步骤**：
1. 销毁 ghost 元素（从 DOM 移除）。
2. 清除所有块的 `transform` 和 `transition`（恢复原始布局）。
3. 恢复源块 `opacity` 为正常值。
4. 恢复 `user-select`。
5. 提交 ProseMirror 事务：将 `sourceBlock` 移动到最终计算的插入位置（`pointercancel` 时跳过此步，保持原位）。

**系统响应**：
- 提交事务后，ProseMirror 重新渲染文档，块顺序与拖拽结果一致。
- 整个过程用户感知为「块平滑移动到新位置」，无闪烁。

**异常/边界路径**：
- ProseMirror 事务提交失败（如文档已被并发修改）：回滚视觉状态（块回到原位），不崩溃，不留残留 DOM。
- `pointerup` 触发两次（部分浏览器行为）：清理操作幂等，不重复提交事务。

## 不在本期

- 触摸屏拖拽（touch events）支持：pointer events 在触摸屏上可工作，但触摸拖拽的 UX 细节（长按激活、滚动冲突）单独处理，不在本期。
- 跨页面拖拽：不在本期。
- 列布局（左/右半区）创建：维持现有行为，不在本期重构。
- 拖拽排序动画的缓动曲线精细调优：本期以 `150ms ease` 为默认值，后续可按需调整。

## 场景矩阵

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 向下拖拽块，指针悬停在目标块下半部分 | 目标块下边缘显示蓝色横线；中间块向上让位；ghost 半透明跟随指针 |
| 输入有效性 | 向上拖拽块，指针悬停在目标块上半部分 | 目标块上边缘显示蓝色横线；中间块向下让位；ghost 半透明跟随指针 |
| 输入有效性 | 拖拽块，指针悬停在源块自身 | 不触发让位，不显示指示线，ghost 正常跟随 |
| 输入有效性 | pointerdown 时目标块 DOM 节点不存在 | 不进入拖拽状态，不报错 |
| 数量/规模边界 | 文档只有 1 个块，拖拽该块 | ghost 正常跟随；无让位；pointerup 后位置不变，无残留 DOM |
| 数量/规模边界 | 文档包含 50+ 个块，快速移动指针 | rAF 节流，让位计算每帧一次，无性能卡顿；拖拽结束后无残留 |
| 前置条件/状态 | 拖拽进行中编辑器组件卸载 | destroy() 清理 ghost、恢复所有 transform 和 opacity，不产生内存泄漏 |
| 前置条件/状态 | pointerup 后立即开始新一次拖拽 | 前一次 ghost 和 transform 已清理；新一次拖拽状态正确初始化 |
| 前置条件/状态 | pointercancel（系统手势打断） | 执行与 pointerup 相同清理，不提交位置变更，块回到原位 |
| 前置条件/状态 | 拖拽过程中 ProseMirror 事务提交失败 | 视觉状态回滚（块回原位），不崩溃，不留残留 DOM |
| 幂等性 | pointermove 在同一帧内多次触发 | rAF 节流，每帧只执行一次让位计算，无重复 DOM 操作 |
| 幂等性 | pointerup 触发两次（部分浏览器行为） | 清理和事务提交为幂等操作，第二次无副作用 |

**不适用维度说明**：「来源/优先级」不适用，pointer events 来源单一（用户指针），无多来源竞争场景。

## 验收标准

- [ ] 拖拽块时，ghost 元素半透明（`opacity: 0.6`）实时跟随指针，不使用浏览器原生 drag image
- [ ] `pointermove` 期间，源块与目标插入点之间的所有块通过 `transform: translateY` 实时让位，过渡动画 150ms
- [ ] 目标插入位置显示蓝色横线（2px，`rgba(59, 130, 246, 0.9)`），位置随指针实时切换（上/下半区）
- [ ] `pointerup` 后，ProseMirror 事务提交，块顺序与拖拽结果一致；ghost、transform、opacity 全部清理，无残留 DOM
- [ ] `pointercancel` 后，视觉状态回滚，块回到原位，不提交事务，无残留 DOM
- [ ] 编辑器卸载时（`destroy()`），ghost 和所有临时状态被清理，不产生内存泄漏
- [ ] 50+ 块文档中快速拖拽，无明显卡顿（rAF 节流生效）
- [ ] `tsc --noEmit` 零错误
- [ ] 改动仅限 `web/src/components/editor/` 目录，不修改其他模块
