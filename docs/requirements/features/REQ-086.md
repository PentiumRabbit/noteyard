## 背景

noteyard 的块拖拽排序功能由 `web/src/components/editor/dropOverlayPlugin.ts` 实现，目前拖拽时仅在目标块上叠加一个蓝色半透明填充框（`bn-drop-overlay`）。

用户反馈此视觉反馈不直观：
- 无法明确看出块将被插入到目标块的**上方还是下方**；
- 被拖拽的块在拖拽过程中没有半透明 ghost 跟随效果，视觉上缺乏「正在移动」的感知；
- 整体体验与 Notion 等同类产品存在明显差距。

REQ-086 在不破坏现有拖拽逻辑（ISS-048 修复成果）的前提下，增强拖拽过程中的视觉反馈。

---

## 目标

拖拽块时，用户能通过以下视觉信号明确感知「拖拽中」状态与「将插入到哪里」：
1. 被拖拽块以半透明 ghost 形式显示（跟随浏览器原生 drag image）；
2. dragover 目标位置以蓝色横线（插入指示线）替代当前蓝色填充框，明确指示插入点（上方或下方）；
3. 其他块不需要真正实时移动（ProseMirror 限制），插入指示线已足够表达意图。

---

## 功能需求

### FR-1 被拖拽块 ghost 半透明效果（MVP）

**触发条件**：用户通过 BlockNote 拖拽手柄开始拖拽一个块（`dragstart` 事件）。

**操作步骤**：
1. 用户按住拖拽手柄并开始移动。
2. 浏览器触发 `dragstart`，系统捕获该事件。
3. 系统通过 `event.dataTransfer.setDragImage` 设置自定义 drag image：克隆目标块 DOM 节点，设置为半透明（`opacity: 0.5`），附加到 body（屏幕外），作为 drag image 传入。
4. 拖拽过程中，鼠标跟随的 ghost 图像呈现半透明效果。
5. 拖拽结束（`dragend` / `drop`）后，临时附加的克隆节点从 DOM 中移除。

**系统响应**：
- 原块在文档中的位置不变，仅 drag image 呈半透明。
- 克隆节点不可交互（`pointer-events: none`），不影响拖拽目标检测。

**异常/边界路径**：
- `dragstart` 时找不到目标块 DOM 节点：跳过自定义 drag image，使用浏览器默认行为，不报错。
- `event.dataTransfer` 为 null（非标准浏览器）：跳过，不崩溃。
- 拖拽过程中编辑器卸载：`dragend` 清理逻辑在 `DropOverlayView.destroy()` 中执行，确保克隆节点被移除。

---

### FR-2 插入位置蓝色横线指示（MVP）

**触发条件**：拖拽进行中，`dragover` 事件触发，目标块为「普通排序」（`position === "regular"`）。

**操作步骤**：
1. 用户拖拽块并悬停在目标块上。
2. 系统计算鼠标 Y 坐标相对目标块 rect 的位置：
   - 鼠标在目标块上半部分（`clientY < rect.top + rect.height / 2`）→ 指示线显示在目标块**上边缘**；
   - 鼠标在目标块下半部分 → 指示线显示在目标块**下边缘**。
3. 蓝色横线覆盖目标块全宽，高度 2px，颜色 `rgba(59, 130, 246, 0.9)`，不再显示填充框。
4. 鼠标移动时，指示线实时更新位置（上/下切换）。

**系统响应**：
- 指示线通过现有 `bn-drop-overlay` 元素实现，替换当前填充框样式为细横线样式。
- 指示线 `position: fixed`，`pointer-events: none`，`z-index: 50`，不影响其他交互。
- `dragleave` / `dragend` / `drop` 时，指示线与现有逻辑一致被移除。

**异常/边界路径**：
- 目标块为列布局（`position === "left"` 或 `"right"`）：保持现有填充框行为不变（列创建意图需要填充框区分左右半区）。
- 目标块 rect 高度为 0：跳过显示，不报错。
- 多个 `dragover` 事件在同一帧内触发：以最后一次为准（现有节流逻辑不变）。

---

### FR-3 拖拽结束后清理（MVP）

**触发条件**：`dragend` 或 `drop` 事件触发。

**操作步骤**：
1. 移除插入指示线（`removeOverlay()`，现有逻辑）。
2. 移除 FR-1 中附加到 body 的 ghost 克隆节点（若存在）。

**系统响应**：拖拽结束后页面恢复正常，无残留 DOM 节点或视觉元素。

**异常/边界路径**：
- 克隆节点已被提前移除（如编辑器卸载）：`destroy()` 中幂等检查，不重复操作。

---

## 不在本期

- 其他块实时让位（真实 DOM 重排）：ProseMirror 不支持非事务性 DOM 变更，实现复杂度过高，不在本期。
- 拖拽动画（缓动、过渡效果）：浏览器原生 drag API 限制，不可控，不在本期。
- 触摸屏拖拽（touch drag）支持：BlockNote 原生不支持，不在本期。
- 跨页面拖拽：不在本期。

## 场景矩阵

**场景矩阵**:（格式见 docs/engineering/templates/scenario-matrix-template.md）

| 维度 | 场景 | 预期行为 |
|------|------|---------|
| 输入有效性 | 拖拽普通段落块，悬停在另一段落块上半部分 | 目标块上边缘显示蓝色横线；ghost 半透明跟随鼠标 |
| 输入有效性 | 拖拽普通段落块，悬停在另一段落块下半部分 | 目标块下边缘显示蓝色横线；ghost 半透明跟随鼠标 |
| 输入有效性 | 拖拽块至目标块左侧 15% 区域内（列创建意图） | 显示左半区填充框（现有行为），不显示横线 |
| 输入有效性 | 拖拽块至目标块右侧 15% 区域内（列创建意图） | 显示右半区填充框（现有行为），不显示横线 |
| 输入有效性 | dragstart 时目标块 DOM 节点不存在 | 使用浏览器默认 drag image，不报错，拖拽正常进行 |
| 数量/规模边界 | 文档只有 1 个块，拖拽该块 | dragover 无目标块，指示线不显示；dragend 后无残留 DOM |
| 数量/规模边界 | 文档包含 50+ 个块，快速拖拽移动 | 指示线实时跟随，无性能卡顿；拖拽结束后无残留节点 |
| 前置条件/状态 | 拖拽进行中编辑器组件卸载 | destroy() 清理克隆节点和指示线，不产生内存泄漏 |
| 前置条件/状态 | 拖拽结束（drop）后立即开始新一次拖拽 | 前一次 ghost 克隆节点已清理；新一次 ghost 正确生成 |
| 前置条件/状态 | 拖拽块到编辑器区域外（dragleave 编辑器根节点） | 指示线移除（现有行为），ghost 克隆节点在 dragend 时移除 |
| 幂等性 | 同一拖拽过程中多次触发 dragover | 指示线位置以最后一次 dragover 结果为准，无重复 DOM 节点 |
| 幂等性 | dragend 触发两次（部分浏览器行为） | 第二次 removeOverlay / 克隆节点清理为幂等操作，不报错 |

**不适用维度说明**：「来源/优先级」不适用，拖拽事件来源单一（浏览器原生 drag API），无多来源竞争场景。

## 验收标准

- [ ] 拖拽块时，鼠标跟随的 ghost 图像呈半透明效果（`opacity: 0.5`），而非浏览器默认不透明截图
- [ ] dragover 普通排序场景下，目标块显示蓝色横线（2px 高），而非蓝色填充框；横线位置根据鼠标在目标块上/下半部分实时切换
- [ ] 列创建场景（左/右 15% 区域）保持现有填充框行为不变，ISS-048 修复成果不受影响
- [ ] 拖拽结束后（drop 或 dragend），指示线和 ghost 克隆节点均从 DOM 中移除，无残留
- [ ] 编辑器卸载时（`DropOverlayView.destroy()`），ghost 克隆节点被清理，不产生内存泄漏
- [ ] `tsc --noEmit` 零错误
- [ ] 改动仅限 `web/src/components/editor/` 目录，不修改其他模块
