## 背景与目标

欢迎页（page ID `00000000-0000-0000-0000-000000000001`）的内容通过 `server/internal/db/seeds/welcome.json` 在数据库初始化时写入，作为新用户的使用说明和块类型展示台。

当前 `ApplySeed` 的幂等性策略是"page 已存在则跳过"，只保护页面不被重复创建，不保护页面的 blocks。用户将欢迎页内所有块全部删除后，页面变为空白，重启应用也不会恢复，因为 page 记录依然存在。

**目标：当应用启动时检测到欢迎页 blocks 数量为 0，自动将 `welcome.json` 中的 blocks 重新写入，使欢迎页恢复为默认内容。**

---

## 触发条件

满足以下全部条件时，执行恢复操作：

1. page ID `00000000-0000-0000-0000-000000000001` 在 `pages` 表中存在
2. 该 page 下 `blocks` 表中的顶层块数量为 **0**（`SELECT COUNT(*) FROM blocks WHERE page_id = ? AND parent_block_id IS NULL`，结果为 0）

仅检查顶层块数量（`parent_block_id IS NULL`）即可判断欢迎页是否已被清空，因为子块（column 内的 paragraph 等）不会脱离父块独立存在。

---

## 恢复时机

**应用启动时，sidecar 初始化阶段**，在现有 seed 加载逻辑（`ApplySeed`）完成之后立即执行检测与恢复。

不做实时检测（不监听删除事件、不在每次 API 请求时检查），只在每次启动时检测一次。

---

## 恢复范围

- **恢复：** 将 `welcome.json` 的 `blocks` 数组重新写入数据库，block ID 与 seed 文件中的 ID 一致
- **不恢复：** page 元数据（`title`、`icon`、`order_index`、`created_at`）保持数据库中的现有值不变，不从 seed 覆盖

恢复时所有旧 blocks 已不存在（用户主动删除），直接 INSERT 即可，无需先 DELETE。若因异常导致部分 blocks 残留（`parent_block_id IS NULL` 数量为 0 但子块有孤儿记录），实现层应在 INSERT 前先执行 `DELETE FROM blocks WHERE page_id = ?` 清理孤儿块，确保数据一致。

---

## 用户感知

- 恢复操作**静默执行**，不弹出任何提示或通知
- 用户下次打开欢迎页时，看到内容已恢复为默认状态
- 恢复后的欢迎页内容与全新安装时的欢迎页内容完全一致

---

## 不在范围

- **其他普通页面：** 只有欢迎页（固定 page ID）触发此逻辑，其他页面被清空不做任何恢复
- **"重置为默认"按钮：** 不提供用户主动触发重置的 UI 入口
- **欢迎页设为只读：** 用户仍可自由编辑和删除欢迎页内容，行为与当前一致
- **page 元数据恢复：** title、icon 被用户修改后不会被还原
- **部分删除恢复：** 仅当 blocks 数量为 0 时才恢复，用户删除部分块不触发恢复

---

## 实现指引（供开发参考，非约束性）

在 `loader.go` 或调用方中，在 `ApplySeed` 之后增加一个新函数，例如 `RestoreWelcomeIfEmpty`：

```
func RestoreWelcomeIfEmpty(tx *sql.Tx, page *SeedPage, blocks []SeedBlock) error
```

逻辑：
1. 查询 `SELECT COUNT(*) FROM pages WHERE id = ?`，page 不存在则跳过（`ApplySeed` 尚未执行或数据库异常，不干预）
2. 查询 `SELECT COUNT(*) FROM blocks WHERE page_id = ? AND parent_block_id IS NULL`
3. 若数量 > 0，跳过
4. 若数量 = 0，先执行 `DELETE FROM blocks WHERE page_id = ?`（清理可能的孤儿块），再将 `blocks` 批量 INSERT，`order_index` 与 seed 解析结果一致，`created_at`/`updated_at` 使用当前时间

---

## 验收标准

- [ ] 全新安装启动后，欢迎页正常显示 seed 内容（原有行为不受影响）
- [ ] 在欢迎页中全选所有块并删除，重启应用后，欢迎页恢复为默认内容，所有块正常渲染
- [ ] 恢复后的欢迎页 page 元数据（title、icon）与删除前保持一致，未被 seed 覆盖
- [ ] 恢复过程中不弹出任何提示或通知
- [ ] 欢迎页内容部分被删除（仍有块存在）时，重启应用不触发恢复
- [ ] 除欢迎页以外的普通页面被清空后，重启应用不触发任何恢复逻辑
- [ ] 欢迎页恢复后，用户可正常继续编辑（非只读）
- [ ] 数据库中不残留孤儿块（`parent_block_id` 指向不存在的块）
