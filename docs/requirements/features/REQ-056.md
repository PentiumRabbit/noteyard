## 背景

汇总列（Rollup）基于关联列（REQ-055）对目标数据库中被关联行的某一列进行聚合计算，输出单个值（如计数、求和、最大值等），对齐 Notion Rollup 列的核心语义。

汇总列在概念上与 formula 列类似（均为只读、派生列），但数据来源是跨库关联行，而非同行其他列。现有的 formula 列实现（`formulaEngine.ts`、`server/internal/repository/sqlite/formula_eval.go`）提供了架构参考。

现有技术基础：
- `DBColumn.options` 存储列配置（关联列已经复用），汇总列同样使用此字段
- formula 列在 `database_repo.go` 的 `ListRows` 中计算并注入 `row.Cells`，汇总列采用同样策略
- 前端 formula 列渲染为只读 span，汇总列遵循同样模式
- `READONLY_COL_TYPES` Set 已存在，汇总列应加入其中

## 用户故事

作为 noteyard 用户，我希望在数据库 A 中为一个关联列添加汇总列，自动计算被关联行的某列聚合值（如：关联订单数量、关联金额总和），省去手动统计的工作。

## 数据模型

### 列类型

`DBColumn.type` 新增枚举值 `"rollup"`。

### 列配置（options 字段）

```typescript
interface RollupColumnOptions {
  relation_column_id: string;    // 当前数据库中关联列的 ID
  target_column_id: string;      // 目标数据库中被聚合列的 ID
  aggregation: RollupAggregation;
}

type RollupAggregation =
  | "count"           // 计数（全部）
  | "count_not_empty" // 计数（非空）
  | "sum"             // 求和
  | "avg"             // 平均值
  | "max"             // 最大值
  | "min"             // 最小值
  | "show_original";  // 显示原始值（逗号拼接）
```

`DBColumn.options` = `JSON.stringify(RollupColumnOptions)`

### 单元格值格式

汇总列为派生列，`database_cells` 中**不存储**汇总值，所有值在 `ListRows` 时由后端实时计算并注入 `row.Cells[column_id]`，与 formula 列处理方式一致。

### 后端计算逻辑

```
对于每个 rollup 列:
  1. 解析 options 获取 relation_column_id、target_column_id、aggregation
  2. 对每一行，读取 cells[relation_column_id] → JSON.parse → []rowID
  3. 查询目标数据库中这些 rowID 对应的 cells[target_column_id] 值
  4. 按 aggregation 计算结果，写入 row.Cells[rollup_column_id]
```

批量优化：在 `ListRows` 时，对全部行的关联 row ID 做去重后一次性批量查询 `database_cells`，避免 N+1。

## 验收标准

- [ ] 「新增列」弹窗中可选「汇总」类型，并配置关联列 / 目标属性 / 聚合函数；列头图标为 Σ，刷新后持久
- [ ] 支持 7 种聚合函数：count、count_not_empty、sum、avg、max、min、show_original
- [ ] 汇总列只读，不可点击编辑，`READONLY_COL_TYPES` 包含 `"rollup"`
- [ ] 聚合结果在后端 `ListRows` 时计算，与 formula 列的注入方式一致
- [ ] 关联列/目标列被删除后，汇总列显示空，不崩溃
- [ ] options JSON 损坏时，汇总列降级为空，不抛未捕获异常
- [ ] 空关联行的数字聚合结果为 0，不抛异常
