# REQ-076 前端日志本地文件持久化

## 背景

当前前端日志采用三层方案：console → localStorage（最多 500 条）→ backend `/api/log`。

localStorage 是内存级别的缓冲，容量有限（500 条 FIFO），应用重启后仍在，但无法被外部工具读取，也不能用于跨会话的完整诊断。

用户希望前端日志有完整的本地文件持久化，支持按天滚动和自动清理。

## 需求

### 功能要求

1. 前端产生的 INFO/WARN/ERROR 日志写入本地文件（DEBUG 级别在生产构建跳过，与现有逻辑一致）
2. 日志文件按天滚动：`frontend-YYYY-MM-DD.log`，每行一条 JSON
3. 自动清理：超过 7 天的旧文件在每次写入时异步检查并删除
4. 写入路径：`{app_local_data_dir}/logs/frontend-YYYY-MM-DD.log`（与 server.log 同目录）
5. 非 Tauri 环境（浏览器调试、Vite dev server）不写文件，静默降级，不报错

### 实现方式

通过 Tauri command 实现（Rust 侧写文件），前端调用 `invoke("write_frontend_log", { level, msg, fields })`。

**Rust command 职责**：
- 接收 `level: String, msg: String, fields: Option<Value>`
- 获取 `app_local_data_dir/logs/`，构造当天文件名
- 追加写入一行 JSON（`{ time, level, msg, fields? }`）
- 扫描目录，删除超过 7 天的 `frontend-*.log` 文件（只删 frontend- 前缀）

**TypeScript 侧职责**：
- `logger.ts` 在 `send()` 末尾追加 `invoke("write_frontend_log", ...)` 调用
- catch 后静默忽略（非 Tauri 环境 invoke 会 throw）
- 不影响现有三层逻辑（此为第四层，最低优先级）

### 不在范围内

- 日志查看 UI（读取文件展示给用户）
- 日志上报到远端服务器
- 压缩旧文件

## 验收标准

- macOS 应用运行后，`~/Library/Application Support/com.noteyard.app/logs/` 目录出现 `frontend-YYYY-MM-DD.log`
- 连续运行超过 7 天（或模拟写入旧日期文件），8 天前的文件被自动删除
- 在 Vite dev server（非 Tauri 环境）中打开，不出现任何错误
- 应用崩溃或强制退出后，崩溃前的日志仍在文件中

## 优先级

P2 — 改善诊断能力，不阻塞核心功能
