## 背景

noteyard 当前完全没有日志能力，排查问题只能依赖系统日志或 WebView 调试工具，效率极低。作为 Tauri v2 桌面应用，noteyard 包含三个独立运行层：前端（React/TypeScript）、Go 后端 sidecar、Rust Tauri 层，三层均需要结构化日志写入本地文件，便于用户反馈问题时快速定位。

此能力同时作为工程规范沉淀，要求架构师在新建任何桌面应用项目时主动纳入日志基础设施评审。

---

## 范围

### 一、前端层（React/TypeScript）

**写入目标**：通过 Tauri `invoke` 将日志写入 Go sidecar（由 Go 统一写文件），或直接通过 Tauri 插件写入本地日志文件。

**方案选择**：

| 方案 | 说明 | 结论 |
|------|------|------|
| 调用 Go sidecar 写日志 | 前端通过 HTTP 调用 Go 的 `/log` 端点，Go 统一写文件 | **推荐**，日志集中，格式统一 |
| Tauri plugin-log | 使用 `@tauri-apps/plugin-log`，日志走 Rust 层 | 备选，依赖 Rust 插件配置 |

**推荐方案**：前端调用 Go sidecar 的日志端点，由 Go 统一负责写文件。前端封装一个 `logger` 模块（`web/src/lib/logger.ts`），对外暴露 `debug / info / warn / error` 四个函数，内部格式化日志条目后调用 Go 端点。

**日志格式**（JSON Lines）：
```
{"ts":"2026-05-04T10:00:00.000Z","level":"INFO","layer":"frontend","msg":"页面加载完成","page_id":"abc123"}
```

**日志级别**：DEBUG / INFO / WARN / ERROR

- DEBUG：仅在开发模式（`import.meta.env.DEV`）下发送，生产构建默认关闭
- INFO：正常操作节点（页面打开、保存成功等）
- WARN：可恢复错误（网络超时重试、格式兼容降级等）
- ERROR：需要用户感知或需排查的异常（API 调用失败、渲染崩溃等）

---

### 二、Go 后端 sidecar 层

**写入目标**：直接写本地文件，使用 `lumberjack` 或标准库实现日志轮转。

**库选型**：
- 日志框架：`log/slog`（Go 1.21+ 标准库，无需额外依赖）
- 轮转：`gopkg.in/natefinish/lumberjack.v2` 或 `github.com/natefinch/lumberjack`（事实标准，支持大小/时间双维度轮转）

**日志格式**（JSON Lines）：
```
{"time":"2026-05-04T10:00:00.123456789+08:00","level":"INFO","source":{"file":"server/pages.go","line":42},"msg":"页面保存完成","page_id":"abc123"}
```

**日志文件路径**（见下文统一路径定义）

**日志级别**：DEBUG / INFO / WARN / ERROR，对应 `slog.Level`

- 通过环境变量或配置项控制最低级别，生产默认 INFO，开发模式默认 DEBUG
- 新增 `/internal/log` 包，初始化全局 logger，供各模块直接引用

**额外能力**：
- 接收前端日志写入请求：新增 `POST /api/log` 端点，接收 `{level, layer, msg, fields}` 写入同一文件（或独立前端日志文件，视实现简洁度决定）
- 应用启动/关闭时记录 INFO 日志

---

### 三、Rust Tauri 层

**写入目标**：使用 `tauri-plugin-log` 写入本地文件。

**库选型**：`tauri-plugin-log`（Tauri 官方插件，支持文件、stdout、WebView 多目标）

**配置要点**：
- 开启 `targets: [LogTarget::LogDir { file_name: "tauri" }, LogTarget::Stdout]`
- 日志目录使用 `tauri::api::path::app_log_dir()`（自动对应系统标准日志目录，见下文）
- 最低级别：生产 INFO，开发 DEBUG
- 在 `tauri.conf.json` 的 `bundle > resources` 无需额外配置；插件在 `lib.rs` 中注册

**日志格式**：`tauri-plugin-log` 默认格式，含时间戳、级别、模块路径、消息

## 日志文件路径

各层日志统一写入系统标准应用数据目录下的 `logs/` 子目录：

| 平台 | 基础路径 | 完整日志目录 |
|------|---------|------------|
| macOS | `~/Library/Application Support/com.noteyard.app/` | `~/Library/Application Support/com.noteyard.app/logs/` |
| Windows | `%APPDATA%\com.noteyard.app\` | `%APPDATA%\com.noteyard.app\logs\` |
| Linux | `~/.local/share/com.noteyard.app/` | `~/.local/share/com.noteyard.app/logs/` |

各层对应文件：

| 层 | 文件名 | 示例 |
|----|--------|------|
| Go sidecar（含前端转发） | `server.log` | `…/logs/server.log` |
| Rust Tauri | `tauri.log` | `…/logs/tauri.log` |

Go 层通过 `tauri::api::path::app_local_data_dir()` 由 Tauri 在启动时将日志目录路径通过环境变量或命令行参数传递给 sidecar，sidecar 优先使用该路径，回退到 `./logs/`。

---

## 日志级别分层

| 级别 | 说明 | 典型场景 |
|------|------|---------|
| DEBUG | 开发调试信息，生产不写 | 函数进入/退出、SQL 参数、HTTP 请求体 |
| INFO | 正常业务节点 | 应用启动、页面保存、数据库迁移完成 |
| WARN | 可恢复异常，不影响主流程 | 配置项缺失使用默认值、重试成功 |
| ERROR | 需关注的错误，影响功能或用户操作 | API 调用失败、文件读写失败、崩溃恢复 |

---

## 日志轮转策略

所有层均要求日志文件轮转，防止磁盘空间无限增长：

| 维度 | 策略 | 说明 |
|------|------|------|
| 单文件大小上限 | 10 MB | 超出后自动轮转 |
| 保留文件数 | 最多 5 个备份 | `server.log.1` ~ `server.log.5` |
| 压缩 | 备份文件 gzip 压缩 | 节省磁盘空间 |
| 时间轮转 | 可选，按天轮转 | 与大小轮转配合，取先达到者 |

**Go 层**：通过 `lumberjack` 配置 `MaxSize: 10`（MB）、`MaxBackups: 5`、`Compress: true`。

**Rust 层**：`tauri-plugin-log` 当前版本支持按大小轮转，通过 `max_file_size` 配置（bytes）；不支持压缩时接受纯文本备份文件。

**前端**：日志经由 Go 层写入，轮转策略同 Go 层。

---

## 不在范围

- 日志查看 UI（无 GUI 日志浏览器，纯后台能力）
- 日志上传 / 远程收集（所有日志仅本地存储）
- 结构化查询（不提供日志搜索 API）
- 日志加密
- 用户可配置日志级别的设置页面（本期由代码/环境变量控制，后续需求另立）

本需求的规范沉淀是交付物的一部分，要求在实现完成后同步完成以下沉淀：

- Rust `tauri-plugin-log` 注册与配置要点
