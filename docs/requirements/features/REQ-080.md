# REQ-080 Go server 固定端口支持

| 字段 | 内容 |
|------|------|
| REQ ID | REQ-080 |
| 版本 | v1.0 |
| 状态 | 已完成 |

| 优先级 | P2 |
| 来源 | 用户反馈 |

## 背景

noteyard Go server 目前在启动时自动选取随机端口。Tauri 客户端通过 `invoke('get_port')` IPC 接口获取实际端口后与 server 通信。

浏览器/开发模式下无法调用 Tauri IPC，前端回退（fallback）写死为 8080，导致在浏览器直接访问时无法连接 Go server（server 实际监听端口与前端假设端口不一致）。

为使前端在浏览器模式下也能正常访问 server，需要支持在启动 server 时通过命令行参数指定固定监听端口，并由 Tauri 客户端在启动 sidecar 时将自身所用端口传入 server，保证客户端与 server 端口一致。

---

## 目标

1. Go server 支持通过命令行参数指定监听端口，解除对随机端口的强依赖。
2. Tauri 客户端启动 sidecar 时主动将端口参数传入，确保 `get_port` 返回值与 server 实际端口始终一致。
3. 不强制改变开发模式或 Makefile 的启动方式，保持向后兼容。

---

## 功能需求

### FR-1 Go server — `--port` 命令行参数

- Go server 支持 `--port <number>` 命令行参数。
- 若传入 `--port`，server 监听该指定端口。
- 若未传入 `--port`，server 沿用现有随机端口逻辑，行为不变。
- `--port` 参数值须为合法端口号（1–65535）；传入非法值时 server 启动失败并输出明确错误信息。

### FR-2 Tauri — sidecar 启动时传入端口参数

- Tauri 客户端在启动 Go sidecar 时，将自身已确定使用的端口作为 `--port` 参数传给 sidecar。
- 启动完成后，`invoke('get_port')` 返回的端口号与 server 实际监听端口一致。
- Tauri 侧端口获取/确定时机早于 sidecar 启动，且不依赖 IPC 之外的外部资源。

### FR-3 向后兼容

- 不传 `--port` 参数时，Go server 行为与现有版本完全相同（随机端口）。
- Makefile 及前端 `main.tsx` 无强制改动要求；开发者可自行决定是否在开发时传入固定端口。

---

## 验收标准

| # | 场景 | 预期结果 |
|---|------|---------|
| T1 | 以 `--port 8765` 启动 Go server，访问 `http://localhost:8765/api/health`（或同等健康检查端点） | 返回 200，server 正常响应 |
| T2 | 不传 `--port` 启动 Go server | server 正常启动，端口随机，现有行为不变 |
| T3 | 以非法端口（如 `--port 0` 或 `--port 99999`）启动 Go server | server 启动失败，终端输出包含端口无效的错误信息，进程退出码非零 |
| T4 | Tauri 客户端启动后，在客户端内调用 `invoke('get_port')` | 返回值与 Go server 实际监听端口相同 |
| T5 | Tauri 客户端启动后，前端通过 `get_port` 返回的端口发起 API 请求 | 请求成功，无连接拒绝（connection refused）错误 |
| T6 | Tauri 客户端多次重启（关闭并重新打开应用） | 每次 `get_port` 返回值与当次 server 实际端口一致，不出现端口错位 |

---

## 不在范围内

- 前端 `main.tsx` fallback 端口值的修改（由开发者自行决定）。
- Makefile 开发启动命令的修改（由开发者自行决定）。
- 端口冲突自动重试或端口扫描逻辑（超出本次范围）。
- 端口配置持久化（如写入配置文件）。
- 多实例并发启动的端口隔离。
